# Addendum — appintoss PRD

이 문서는 PRD 본문에 넣기엔 too-implementation-specific한 밸런스 초안과 후속 조치 메모를 담는다. **여기 적힌 수치는 전부 개발 착수용 시작점이며, PRD가 확정한 요구사항이 아니다.** 실제 값은 플레이테스트로 조정한다 (PRD §4.1 FR-2/FR-3/FR-4/FR-5/FR-7, §4.2 FR-10/FR-12, §4.4 FR-18, §12 Open Question #6/#9 참고).

## 제한시간 밸런스 초안 (플레이테스트 전 시작값)

- 스테이지 1~3: 고정 15초 (튜토리얼 그레이스 구간, FR-9 암묵적 온보딩과 연동)
- 스테이지 4 이후: 스테이지당 -1초, 하한선 5초
- 오답(미스매치) 1회당: -3초 즉시 차감
- 타이머 0 도달: 스테이지 실패 → 보상형 광고 시청 시 시간 회복 후 이어하기, 또는 무료 재시도(단, 동일 스테이지 연속 무료 재시도는 최대 2회 — 아래 참고)

**조정 신호**: 플레이테스트에서 스테이지 4~6 근처에서 대부분의 유저가 탈락한다면 감소폭(-1초)이나 오답 페널티(-3초)를 완화. 반대로 스테이지 10+ 까지 쉽게 도달하면 압박이 부족하므로 감소폭 강화.

## 퍼즐 난이도(그리드 크기 + 아이콘 유사도 + 보조 도형 배지) 밸런스 초안 — FR-4 `[2026-07-19 재설계, 같은 날 접근성 충돌로 배지 방식으로 확정]`

**`[SUPERSEDED 2026-07-19]`** 바로 아래 문단은 같은 날 오전 게임 아키텍처 세션에서 나온 이전 결정이며, 오후 재미요소/난이도 논의에서 다른 방향으로 대체됐다 — 원문은 보존만 하고 더 이상 유효하지 않다:
> ~~현재 `TILE_ICONS`는 12종 고정이라 그리드 상한(12쌍/24타일)에서 아이콘 종류도 12종으로 막힌다. "패턴 종류 수 증가" 축을 쓰려면 아이콘 풀을 20~30종으로 확장해야 한다.~~
>
> 대체 이유: 아이콘 종류만 늘리는 것은 "더 촘촘하게 구별해야 함"일 뿐 플레이어에게 새로운 스킬을 요구하지 않아 저효율이라는 마스터 판단(2026-07-19) — 새 그림도 필요해 구현 비용도 더 큼. 아래 그룹핑+색 변주로 대체하면 아이콘 풀은 기존 12종 그대로 유지된다.

**설계 근거 (시각 탐색 난이도의 3축)**: 시각적 "찾기" 과제의 난이도는 보통 (1) 자극 개수(set size), (2) 타겟-방해물 유사도, (3) 특징 결합 탐색(conjunction search — 모양 하나만 볼 때보다 모양+색을 동시에 봐야 할 때 훨씬 어려움)으로 구성된다. 기존 설계는 (1)만 썼고 모바일 터치 정확도상 상한에 부딪히는 문제가 있었다. (2)·(3)을 추가해 그리드를 더 키우지 않고도 난이도를 계속 올릴 수 있게 한다.

**아이콘 그룹핑 (타겟-방해물 유사도, 신규)**: 기존 12종 아이콘을 실루엣이 비슷한 그룹으로 재분류한다 — 예: 개과(🐶🦊🐺) / 고양이과(🐱🐯🦁) / 곰과(🐻🐼🐨) / 기타(🐰🐷🐮). 초반 스테이지는 그룹 무시하고 12종을 랜덤 혼합(실루엣이 다른 동물끼리라 안 헷갈려 가장 쉬움). 중반부터는 같은 그룹 안에서만 아이콘을 뽑아 등장시켜 실루엣이 비슷한 것들끼리 경쟁시킨다.

**보조 도형 배지 (특징 결합 탐색, 신규) `[2026-07-19 수정 — 색상 대신 도형으로]`**: 처음엔 CSS `hue-rotate` 색상 변형을 검토했으나, 같은 날 진행한 implementation-readiness 체크에서 이미 `final` 상태인 `DESIGN.md`/`EXPERIENCE.md`의 접근성 원칙("매칭 판별은 아이콘 형태로만 — 색상 단독 신호 금지, 색맹 안전")과 정면 충돌한다는 게 확인되어 **색이 아니라 보조 도형(●▲■◆ 등 배지)으로 확정**했다. 각 타일 우측 상단에 작은 배지(원/삼각/사각/다이아 등)를 얹는다 — 새 동물 아트 에셋 불필요(기존 "동물 캐릭터 아트 제작 안 함" 제약과도 그대로 호환). 초반은 모양만 같으면 매치(배지 무시). 후반부터는 모양+배지가 정확히 같아야 매치되도록 해, "같은 동물인데 배지가 다른" 방해물이 화면에 깔리게 만든다 — 배지 간 구분이 도형 자체로 이뤄지므로 색맹/색약 유저도 동일하게 판별 가능하다. 배지에 색을 추가로 입혀도 되지만(Timer bar 임계구간과 같은 "redundant multi-channel signaling" 관행), **색은 항상 보조 신호일 뿐 배지 모양이 유일한 판별 기준**이어야 한다.

**그리드 상한 확장**: 기존 `MAX_TILES=24`는 "아이콘이 12종뿐이라 24타일(12쌍)을 넘으면 아이콘이 중복돼 매치 로직이 꼬인다"는 기술적 제약이었는데, 배지 축 도입으로 이 제약이 사라진다(12종 × 2~4종 배지 = 24~48개 조합 가능). 반면 addendum이 원래 우려했던 "모바일 터치 정확도" 문제는 실제로는 **총 타일 수가 아니라 가로 컬럼 수**에 좌우된다 — 현재 코드(`PuzzlePage.tsx`의 `columns = board.length > 12 ? 4 : 3`)는 컬럼 수가 3~4로 고정돼 있고 타일이 늘면 세로로만 늘어나는 구조라, 총 타일 수를 늘려도 한 칸 크기는 줄지 않는다. 따라서 `MAX_TILES`를 24 → **36(18쌍)**으로 상향하되, **컬럼 수는 4로 유지**한다(5는 실험적으로만, 6 이상은 금지 — 360px 화면 기준 컬럼당 타일 폭이 5컬럼 ~53px, 6컬럼 ~42px로 터치 권장 최소 44px 아래로 떨어짐).

**통합 스테이지 구간표 (초안, 플레이테스트로 조정)**:

| 구간 | 타일 수(페어) | 컬럼 수 | 아이콘 풀 | 매치 조건 |
|---|---|---|---|---|
| 1~5 | 12개(6쌍) | 3 | 전체 12종 랜덤 혼합 | 모양만 |
| 6~10 | 16개(8쌍) | 4 | 같은 그룹 내에서만 등장 | 모양만 |
| 11~15 | 20개(10쌍) | 4 | 같은 그룹 + 배지 2~3종 도입 | 모양+배지 |
| 16~18 | 24개(12쌍, 舊 상한) | 4 | 같은 그룹 + 배지 3~4종 | 모양+배지 |
| 19+ | 36개(18쌍, 新 상한) | 4 | 그룹+배지 고정, 조합 랜덤성 최대화 | 모양+배지 |

**조정 신호**: 그룹핑이 시작되는 스테이지 6 근처에서 오탭이 급증하면 그룹 도입 시점을 늦춘다. 배지 도형끼리도 작은 화면에서 헷갈릴 수 있으니(예: 사각 vs 다이아) 플레이테스트에서 오판별 비율이 높으면 배지 종류를 서로 더 구분되는 도형으로 교체하거나 종수를 줄인다.

## 무료 재시도 상한 — FR-7

- 동일 스테이지 연속 무료 재시도: 최대 2회. 3회차부터는 보상형 광고 시청 필수.
- 다른 스테이지로 진행하거나 앱을 재시작하면 카운트 리셋. (세션 단위 카운트 — 일 단위 아님, 단순화)

**조정 신호**: 광고 시청률이 지나치게 낮으면(유저가 그냥 이탈) 허용 횟수를 3회로 완화. 반대로 광고 회피용 파밍이 관찰되면 1회로 축소.

## 재화 경제 밸런스 초안 — FR-2 / FR-10

재화 단위 자체가 아직 미정(§3 Glossary)이므로 절대값이 아니라 **비율**로 정의한다.

- 스테이지 클리어당 재화 획득: **고정 1단위** (스테이지 난이도와 무관 — 클리어량까지 난이도별로 밸런싱하면 복잡도가 늘어나므로 단순하게 유지)
- 뽑기 비용: **3단위** — 즉 "스테이지 3회 클리어 = 뽑기 1회" 비율
- 광고 시청 무료 뽑기(FR-11)는 이 3판 그라인딩을 우회하는 밸브 — 급하게 아이템이 필요할 때 광고 시청으로 대체

**조정 신호**: 플레이테스트에서 유저가 뽑기까지 너무 오래 기다린다고 느끼면 배수를 2로 낮춘다. 반대로 뽑기가 너무 쉽게 반복되면(광고 시청 유인이 약해지면) 배수를 4~5로 올린다.

## 아이템 밸런스 초안 — FR-12

| 아이템 | 효과 | 초기 제안 등장 확률 |
|---|---|---|
| 시간 회복 | 제한시간 +5초 즉시 추가 | 40% |
| 오답 무효화 | 다음 미스매치 1회 페널티 없음 | 40% |
| 재화 2배 | 다음 스테이지 클리어 시 재화 획득량 2배 | 20% (희귀도 살짝 낮게 — 경제 인플레이션 방지) |

캐릭터/희귀도 등급은 넣지 않는다(PRD §11 counter-metric 참고 — 스코프 재확대 방지 확정).

## 동물 티어 결과 카드 밸런스 초안 — FR-18

판정 기준은 세션 내 도달 스테이지(또는 개인 최고 기록, 어느 쪽이 더 재미있는지는 플레이테스트로 결정)를 기준으로 한다. 초기 제안 구간:

| 티어 | 도달 스테이지 |
|---|---|
| 나무늘보급 | 0~2 |
| 하마급 | 3~5 |
| 사슴급 | 6~8 |
| 여우급 | 9~11 |
| 치타급 | 12~14 |
| 매급 (최상위) | 15+ |

카피 원칙: "당신의 반응속도는 OO세" 같은 나이 환산 표현은 쓰지 않는다(PRD §4.4, §10 참고 — Brain Age/Lumosity 패턴 회피). "측정/검사/진단" 대신 "이번 판 기록", "티어" 등 게임적 표현만 사용.

## 후속 조치 — 이번 PRD 세션 범위 밖

- **gds-ux 재설계 필요 (구체적 항목, 검증 세션 2026-07-18에서 확인)**:
  - `EXPERIENCE.md`의 "타이머·카운트다운 압박 전면 금지" 원칙 자체를 갱신해야 한다 — PRD §4.1이 이를 override했다.
  - `EXPERIENCE.md`의 배너 광고 관련 서술이 옛 FR 번호를 인용하고 있다면 갱신 필요 — 현재 PRD에서 배너 광고 요구사항은 **FR-14**다.
  - `DESIGN.md`의 `legendarySparkle`(레어 등급 캐릭터 뽑기 연출 파티클)은 캐릭터 희귀도 전제로 만들어진 자산인데, PRD §4.1 FR-8 노트는 아이템 희귀도 등급을 **의도적으로 넣지 않기로** 확정했다. 이 이펙트를 폐기할지, 결과 카드(FR-18)의 상위 티어(치타급/매급) 연출로 재활용할지 gds-ux 세션에서 결정 필요 — 지금은 트리거할 FR이 없는 고아 상태다.
  - `DESIGN.md`/`EXPERIENCE.md`의 정보구조(퍼즐/뽑기/도감 3탭)에서 "도감" 탭은 더 이상 존재하지 않는다 — PRD FR-13의 "인벤토리" 화면으로 대체할지, 다른 탭 구성으로 갈지는 gds-ux에서 정할 신규 결정이며 이 PRD는 화면 자체의 존재만 요구할 뿐 IA는 정하지 않는다.
  - `key-collection.html`, `key-gacha.html` 목업은 폐기된 캐릭터 수집 시스템 기준이라 그대로 못 쓴다.
  - 결과 카드(FR-18~19)와 온보딩(FR-9)은 이번 PRD 세션에서 완전히 새로 생긴 화면/흐름이라 목업 자체가 없다 — gds-ux 세션에서 신규 설계 필요.
- **앱인토스 콘솔 작업 필요**: `contactsViral` 사용을 위해 콘솔에서 리워드(이름, 지급 단위, 수량, 일일 제한) 등록 필요. 코드 작업이 아니라 콘솔 설정.
- **미니앱 승인 타임라인 확인 필요**: `contactsViral`은 승인 완료 전 Internal Server Error를 반환하므로, 승인 전/후 단계적 출시(공유 카드만 → 초대 보상 추가) 순서를 실제 승인 타임라인에 맞춰 조율 필요.
