# 시간 회복 아이템 — 적용 피드백 UX 시안 (2026-08-11)

## 배경

`timeBoost`(시간 회복) 아이템이 다음 스테이지에 적용되지 않던 버그를 고치면서(커밋 `4e9290c`), 아이템 동작이 **즉시 효과 → 다음 스테이지 보류 효과**로 바뀌었다.

- **기존(버그)**: 뽑기 화면에서 쓰면 현재 타이머에 즉시 +5초 → 다음 스테이지 진입 시 `timer.reset()`이 덮어써 효과 소멸
- **변경 후**: 사용 시 보류 플래그가 서고, 다음 스테이지가 늘어난 제한시간으로 시작

이 변경으로 **"내 아이템이 실제로 적용됐다"는 인지 문제**가 생겼다. 즉시 효과였을 땐 눈앞의 타이머가 바로 늘어나 피드백이 자명했지만, 보류 효과는 화면이 한 번 바뀐 뒤에 반영되기 때문이다. 특히 평소 제한시간을 의식하지 않는 유저는 "20초"라는 숫자만으로는 차이를 느끼지 못한다.

## 시안 3종

각 파일은 세 프레임(**아이템 사용 직후 / 스테이지 시작 / 대조군(아이템 없음)**)을 가로로 나란히 배치했다. "늘어난 게 보이나?"는 늘어나지 않은 것과 나란히 놓아야만 판단되므로 대조군이 핵심이다. 브라우저에서 직접 열면 "▶ 다시 보기"로 애니메이션을 반복 재생할 수 있다.

| 시안 | 접근 | 상태 |
|---|---|---|
| [A — 보너스 구간 분리 게이지](timeboost-option-a.html) | +5초를 사선 질감의 별도 구간으로 게이지 오른쪽에 이어붙임 | **채택** |
| [B — 초 단위 눈금 게이지](timeboost-option-b.html) | 게이지를 1초=1칸으로 쪼개고 보너스 5칸이 채워짐 | 미채택 |
| [C — 스테이지 시작 브리핑 카드](timeboost-option-c.html) | 시작 전 화면을 멈추고 "15초 → 20초"를 못 박음 | 미채택 |

## 채택: A — 보너스 구간 분리 게이지

**선정 이유**: 게임 흐름을 끊지 않으면서 "게이지 자체가 길어졌다"를 형태로 보여준다. 보너스 구간이 플레이 내내 트랙에 남아 "저기까지가 원래 없던 시간"이 계속 읽힌다. 기존 `timer-track`을 base/bonus 2분할로 바꾸는 수준이라 구현 부담도 가장 작다.

**알려진 약점**: 사선 질감이 20px 트랙 안에서 작게 읽히고, 게이지가 절반쯤 줄면 보너스 구간이 통째로 사라져 후반엔 단서가 스트립 텍스트뿐이다. 플레이테스트에서 인지가 약하면 C의 "원래 15초" 앵커 마커를 얹거나 B로 올리는 경로를 검토한다 — A와 B는 같은 트랙 컴포넌트를 고쳐 쓰는 관계라 마이그레이션이 자연스럽다.

**미채택 사유**:
- **B**: 인지 명확성은 가장 높으나(칸을 셀 수 있음) 게이지 성격이 아날로그→디지털로 바뀌어 기존 인상이 달라지고, 후반 스테이지(5초)에선 칸이 5개뿐이라 눈금이 과해 보인다. 임계 구간 펄스 연출과도 시각적으로 경합한다.
- **C**: 놓칠 수 없다는 게 최대 강점이지만, 이 게임은 스테이지를 빠르게 연달아 도는 아케이드 런 구조(`useRunState`, 런 리셋 모델)라 매 스테이지 모달이 코어루프 템포를 무너뜨린다.

## 게이지 분모 결정 (구현 전제)

세 시안 모두 트랙 최대 폭을 20초 기준으로 잡았으나, 현재 `PuzzlePage.tsx`는 `timeRatio`를 그 스테이지 기본값 대비로 계산해 **항상 100%에서 시작**한다. 이대로면 게이지가 늘어난 걸 표현할 수 없다.

**확정: 기본 제한시간을 100%로 유지하고 보너스만 트랙 밖으로 확장한다.**

분모를 "가능한 최대 시간"(20초)으로 통일하는 대안은 구현이 단순하지만, 후반 스테이지(제한시간 5초)에서 게이지가 항상 25%에서 시작해 "이미 줄어든" 인상을 준다. 후반은 이 게임에서 압박이 가장 큰 구간이라 이 부작용이 크다고 판단했다.
