- **Sources confirmed**: PRD only (`prd-appintoss-2026-07-17/prd.md`). Game brief and market research explicitly excluded — PRD already integrates them per its own Document Purpose section.
- **Stakes**: Commercial. Rationale: real launch to Toss's 30M-user base, ad-monetization live from day one, 30-50대+ target skews toward accessibility-sensitive. Drives a fuller accessibility floor than a jam/hobby project would get.

Rationale: PRD's brand tone ("밝고 친근한, 귀여운 동물") reads as distinctly different from TDS's fintech palette; user picked full creative freedom over platform-visual consistency. TDS *components* (Top, Button, Dialog, Asset) stay as the structural shell per existing code in `src/pages/`, `src/App.tsx` — only the visual token layer (color/type/shape) diverges.
- **Color reference**: User was shown the Lovable prototype screenshot (orange/cream, rounded cards, fruit/animal icons) from the surrounding conversation and explicitly chose *not* to carry its palette forward — asked to set color direction fresh instead.
- **Color direction**: Energy (yellow/teal) — chosen over coral/sand and lavender/mint options. User picked this knowing it skews more energetic/youthful than the alternatives; DESIGN.md notes a guardrail to keep saturation in check so it doesn't read as too young for the 30-50대+ persona.
- **Typography tone**: Rounded and cute over clean/system-native — user prioritized playfulness over the "safer for 30-50대" system-font option.
- **Gacha reveal**: Box/capsule-opening reveal — chosen over card-flip and instant-reveal options as the emotionally important beat of the loop.
- **Accessibility baseline**: Generous (48px+ tap targets, 16px+ body text, WCAG AA) — chosen over standard mobile defaults (44px/14px), consistent with Commercial stakes + older-skewing persona.
- **Grounding pass**: Read `src/App.tsx`, `src/pages/PuzzlePage.tsx`, `package.json`, `granite.config.ts` before drafting — confirmed actual stack (`@apps-in-toss/web-framework`, `@toss/tds-mobile`), current IA (single-page switcher, no bottom nav yet), and existing interaction logic (tap-to-select, 500ms mismatch delay) so EXPERIENCE.md's Component/Interaction sections describe real, buildable behavior rather than an invented architecture.
