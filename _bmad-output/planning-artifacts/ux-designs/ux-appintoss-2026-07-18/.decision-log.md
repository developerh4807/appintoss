### Reaction round — timer HUD refinement (2026-07-19, after first mockup pass)

- **Trigger**: user reviewed the rendered `key-puzzle-main.html` mockups and asked for the timer to feel more urgent and more visually dominant, and pointed out the stage-progress bar (matched-pairs-so-far gauge) is meaningless in a matching game — you're always at 100% the moment you clear, so a progress fill communicates nothing.
- **Progress bar removed entirely.** Not just de-emphasized — cut. Stage number now shows as plain text above the Timer bar; no separate gauge for it. `DESIGN.md`/`EXPERIENCE.md` `progressBar` token and all references removed.
- **Timer bar promoted to the header's visual anchor**: roughly 2x the track height of the old progress bar, full header width, positioned as the dominant element (not sharing visual weight with a second bar anymore).
- **Critical-state escalation**: pulse alone (from the first pass) wasn't judged urgent enough. Added: glow (box-shadow spread) on the bar itself, a larger remaining-seconds numeral, and a screen-edge vignette pulse — deliberately *not* a full-screen color flash, which would be a photosensitivity/seizure risk at the pulse rate being used. This was my call, not something the user specified beyond "more urgent, more animated, more intuitive" — flagged and justified in both spines' Accessibility Floor sections rather than silently assumed.
- **Mockup regenerated in place** (`mockups/key-puzzle-main.html`) reflecting all of the above — screenshotted and visually confirmed in the Browser pane before treating this as settled.

### Reviewer Gate — accessibility lens (2026-07-19)

- User opted into the accessibility lens only (skipped the mechanical rubric walker, given PRD's tight timeline and the fact this session already involved heavy direct back-and-forth on the color/timer/accessibility calls).
- Dispatched one subagent against `DESIGN.md`, `EXPERIENCE.md`, and all three `mockups/*.html`. Full findings: `review-accessibility.md` (2 critical, 1 high, 2 medium, 1 low).
- **Fixed immediately** (mechanical, no scope tradeoff):
  - `inkSecondary` token darkened `#8C8275` → `#726858` (contrast claim in `DESIGN.md` was wrong — actual was 3.57:1, not the stated 4.6:1; new value verified ≈5.18:1). Applied across all three mockups.
  - `error` banned as a direct text-glyph color everywhere (≈2.65:1 on `surfaceBase`, AA fail) — critical timer numeral and mismatch `-3` penalty indicator changed from red text to a white/`surfaceRaised` chip with an `error` border and `inkPrimary` text (≈11:1). Both spines and `mockups/key-puzzle-main.html` updated.
  - Bottom nav active-tab state was color-only (`accent` vs `inkSecondary`, same glyph) — added an `accentLight` background chip behind the active tab's icon so it doesn't rely on color alone. Both spines and both tabbed mockups updated.
  - Screen-reader countdown handling, which the spec had wholesale-deferred to implementation, now has an explicit policy in `EXPERIENCE.md` Accessibility Floor: `aria-live="assertive"` once at critical-threshold entry, once at stage failure — not per-tick.
  - Vignette/pulse frequency stated explicitly in Hz (≈0.83Hz full cycle) rather than only "0.6s," so the photosensitivity safety margin travels with the spec.
  - Added an explicit rationale in `DESIGN.md`/`EXPERIENCE.md` distinguishing the four simultaneous critical-state cues (color+pulse+size+vignette) as redundant multi-channel signaling of *one* message, not four competing messages — addresses the "does this contradict the persona's low-density baseline" finding without stripping the urgency the user explicitly asked for.
- **Deliberately left open, flagged for the user rather than silently resolved**: the WCAG 2.2.1 (Timing Adjustable) gap — the hard per-stage timer has no in-stage accommodation for users who structurally need more time; ad-watch/free-retry only fire after failure. Flagged as `[OPEN — NOTE FOR PM]` in `EXPERIENCE.md` Accessibility Floor. This directly conflicts with the PRD's explicit anti-scope-creep counter-metric (§11), so it's not something a UX session should unilaterally resolve either direction. **User's call (2026-07-19)**: keep it as a logged issue for now, no new accommodation feature added this session — explicitly deferred to a PRD/legal-level decision, respecting the 14-day scope-freeze counter-metric rather than the UX session expanding scope on its own judgment.
