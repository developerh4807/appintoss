## Brand & Style

"맞추는 즐거움"이 감정의 전부다 — 어려운 걸 해냈다는 성취감이 아니라, 짝을 찾았을 때의 작고 확실한 만족감. 그래서 화면은 시험지가 아니라 간식 같아야 한다: 따뜻한 크림 바탕 위에 햇살 같은 옐로우, 그 옆에서 차분히 받쳐주는 딥 틸. 둥근 타이포와 필 모양 버튼으로 각진 데는 없이 전부 손에 쥐면 부드러운 형태다.

동시에 이 게임은 토스 3천만 유저 중 30-50대 이상, 특히 부모 세대를 향한다. 그래서 "귀엽다"는 유치함이 아니라 정돈된 귀여움이어야 한다 — 캔디크러시식 과포화 이펙트나 촘촘한 정보 밀도는 피하고, 화면당 할 일은 하나, 텍스트는 크고, 여백은 넉넉하게 둔다. 그리고 이 앱은 절대 "두뇌 훈련 클리닉"처럼 보여선 안 된다 — 의료적 효능을 암시하는 순간(§ PRD Constraints) 법적 리스크로 직결되므로, 톤은 처음부터 끝까지 "체험/재미" 쪽으로만 기울어 있어야 한다.

옐로우/틸 조합은 코랄/샌드나 라벤더/민트보다 더 에너제틱하고 젊게 읽힐 수 있다는 트레이드오프를 알고 선택한 방향이다 — 채도를 과하게 올리지 않고, 아래 Colors 섹션의 명도/채도 범위를 지켜야 이 타겟에서도 "발랄"이지 "유치"로 넘어가지 않는다.

**`[UPDATED 2026-07-19]` 제한시간 압박과의 공존 원칙**: PRD 개정으로 이 게임의 코어루프에 제한시간 압박이 들어왔다 — 이전 세션에서는 "타이머·카운트다운 압박 전면 금지"가 원칙이었던 것과 정반대다. 이 브랜드는 그럼에도 "간식 같은" 톤을 버리지 않는다: 평상시 타이머는 `accent`/`primary` 톤의 차분한 카운트다운으로 존재감만 알리고, 위기감은 **잔여 시간이 임계 구간(전체의 25% 이하)에 들어갔을 때만** `error` 색 펄스·흔들림으로 확실하게 켠다. 즉 "이 앱은 절제된 상태가 기본값이고, 위기는 명확한 신호로만 짧게 켜진다" — 두뇌 트레이닝 클리닉처럼 시종일관 긴장된 UI가 되는 것과, 압박감이 없어 클리어/실패 기준이 흐릿해지는 것 둘 다를 피하는 절충이다.

**`[NEW 2026-07-19]` 타이머는 헤더의 시각적 주인공이다**: 사용자 피드백에 따라 Timer bar를 헤더에서 가장 눈에 띄는 요소로 격상했다 — 매칭 게임에서 "스테이지 클리어 진행률"은 의미가 없다는 판단 아래 기존 Progress bar(스테이지 진행 게이지)를 완전히 제거하고, 그 자리와 시각적 무게를 전부 Timer bar에 넘겼다. 임계 구간의 위기감도 펄스만으로는 부족하다는 판단에 따라 **화면 가장자리 비네트(테두리 글로우)**를 추가한다 — 다만 화면 전체를 붉게 깜빡이는 풀스크린 플래시는 광과민성 발작 위험 때문에 의도적으로 피하고, 테두리만 은은하게 맥동하는 수준으로 절제한다(Accessibility Floor 참고).

`[NEW 2026-07-19]` 제한시간 바는 새 토큰을 만들지 않고 기존 `accent`(평상시)와 `error`(임계 구간, 잔여 25% 이하)를 그대로 재사용한다 — 위기 신호는 이미 오답 피드백에 쓰이는 `error`로 통일해 유저가 "이 색 = 안 좋은 상황"이라는 하나의 규칙만 학습하면 되게 한다.

`[FIXED 2026-07-19]` `error`(#FF6B5C)는 `surfaceBase`(#FFF8EC) 위에서 ≈2.65:1로 WCAG AA 텍스트 기준(4.5:1)에 크게 못 미친다(`review-accessibility.md` critical 발견) — **`error`는 배경·보더·아이콘 색으로만 쓰고, 본문/숫자 텍스트 글리프 색으로 직접 칠하지 않는다.** 임계 구간의 잔여 초 숫자와 오답 페널티 `-3` 플로팅 텍스트는 `error`로 텍스트 자체를 물들이는 대신, `surfaceRaised` 칩 배경 + `error` 2px 보더 + `inkPrimary` 굵은 텍스트 조합으로 표시한다(대비 ≈11:1, 위기감은 보더 색으로 전달) — § Components "Timer bar" 참고.

Avoid: 순수 레드(`#FF0000`류) 경고색 — 의료/경고 앱처럼 보임. 그라디언트 남발 — 카드 하나 이상엔 쓰지 않는다. 파스텔 톤으로 희석 — 에너지 방향을 골랐으면 채도를 지킨다. 타이머를 평상시부터 `error` 톤으로 물들이는 것 — 임계 구간 신호의 특별함이 사라진다. `error`를 텍스트 글리프 색으로 직접 쓰는 것 — 대비 부족(AA 미달).

## Typography

헤드라인/버튼/스테이지 숫자는 둥근 디스플레이 서체(`display` 토큰)로 "귀엽고 게임답게", 본문·설명 텍스트는 `Pretendard`로 가독성을 확보한다 — 두 서체를 섞는 이유는 30-50대+ 타겟에게 장문 설명(인벤토리 아이템 설명, 광고 시청 안내 등)까지 둥근 서체로 밀어붙이면 오히려 읽기 피로가 커지기 때문이다.

스케일은 16px 베이스에서 16 / 18 / 22 / 28 / 36 — 접근성 베이스라인(본문 16px+)을 하한으로 잡았다. 재화·스테이지 숫자는 `numeric` 토큰(tabular-nums)으로 자릿수가 바뀌어도 레이아웃이 흔들리지 않게 한다. 굵기는 본문 500, 헤드라인/버튼/숫자 강조는 700 — 중간 굵기(600)는 쓰지 않아 위계를 명확히 이분한다.

`[ASSUMPTION]` 카페24 슈퍼매직은 방향성 제안 폰트다. 실제 웹폰트 임베드 전 라이선스 조건(상업적 무료 이용 범위)을 개발 착수 시점에 재확인할 것 — 7일 스코프상 라이선스 이슈로 막히면 즉시 시스템 폰트로 폴백.

## Layout & Spacing

8px 그리드(4/8/12/16/24/32/40). 화면 좌우 마진은 16px 이상 — 접근성 "넉넉하게" 결정에 따라 TDS 기본값보다 한 단계 넓게 잡는다. 단일 컬럼, 모달은 한 겹까지만(공유 시트, 클리어 다이얼로그, 뽑기 결과 — 절대 두 겹으로 쌓지 않는다).

화면 상단은 항상 스테이지/재화 상태(`Top` 헤더 영역), 퍼즐 화면 하단은 고정 배너 광고 슬롯(FR-14, 상시 노출) — 이 앵커는 퍼즐 화면에서 위치가 바뀌지 않는다. `[REMOVED 2026-07-20]` 하단 2탭 네비게이션은 완전히 제거됐다(§ Components "Bottom nav tab") — 뽑기 화면은 더 이상 상시 탭으로 공존하지 않고, 스테이지 클리어 시점에만 진입하는 별도 화면이 됐다. `[FIXED 2026-07-19]` 이전 개정에서 놓쳤던 "3탭" 오기를 2탭으로 정정했던 이력은 § Decision Log에 보존.

## Elevation & Depth

전투 게임처럼 계층이 복잡하지 않다 — 카드/타일은 `surfaceRaised` 위 아주 옅은 그림자(과자 상자를 들어올린 듯한 촉각적 느낌, `0 2px 8px rgba(58,50,42,0.08)` 정도)만 쓰고, 배경(`surfaceBase`)과의 톤 차이로 우선 구분한다. 유일하게 진짜 "떠 있는" 레이어는 뽑기 캡슐 오픈 오버레이와 스테이지 클리어 다이얼로그 — 배경을 어둡게 스크림(60% `inkPrimary`) 처리해 시선을 강제로 고정한다.

## Shapes

전부 둥글다 — 이게 "귀여운" 톤의 핵심 장치다. `rounded/sm`(12px)은 배지·칩, `rounded/md`(20px)는 타일·카드, `rounded/pill`(999px)은 버튼·탭바·재화 배지. 완전한 직각은 화면 어디에도 쓰지 않는다(광고 슬롯 컨테이너 제외 — 광고는 플랫폼 렌더링이라 게임 스킨의 라운딩 규칙을 강제하지 않는다).

## Components

- **Button** — `pill` 필, 기본 `primary` 채움 + `inkPrimary` 텍스트, 최소 48px 높이·너비(접근성 탭 타겟). 보조 버튼은 `accent` 아웃라인 + `accent` 텍스트.
- **Tile (매칭 그리드 셀)** — `rounded/md` 정사각, 기본 `surfaceRaised`, 선택 시 `accentLight` 배경 + `accent` 2px 테두리, 오답 시 `error` 배경 500ms 플래시 후 원상복귀, 매칭 성공 시 `success` 플래시 후 페이드아웃. 아이콘 자체(동물/과일 이모지 또는 커스텀 일러스트)가 매칭 판별 신호 — 배경색은 상태 피드백 전용, 판별 기준 아님.
- **Timer bar (제한시간)** `[UPDATED 2026-07-19]` — 헤더의 시각적 주인공. 예전의 얇은 진행바보다 확연히 두꺼운 `pill` 게이지(트랙 높이 ~20px, 기존 스테이지 진행바의 2배)로 스테이지 번호 텍스트 바로 아래 전체 폭을 차지한다. 평상시 `accent` 필로 차분하게 줄어들고, 잔여 초 숫자는 게이지 옆에 큼직하게(스테이지 번호보다 큰 비중으로) `inkPrimary` 색으로 표시해 "지금 제일 중요한 정보"임을 즉시 알린다. 잔여 25% 이하 진입 시 네 가지 신호가 함께 켜진다 — 이는 같은 하나의 메시지("시간이 얼마 없다")를 색·모션·크기·위치 네 채널로 중복 전달하는 접근성 관행(redundant multi-channel signaling)이지 서로 다른 메시지를 동시에 던지는 과포화가 아니다: (1) 필 색이 `error`로 전환, (2) 0.6초 반주기 펄스(스케일 1.0→1.04, 전체 주기 ≈1.2초/≈0.83Hz — WCAG 2.3.1의 3Hz 기준에 여유 있게 못 미침) + 은은한 `error` 글로우(box-shadow 확산), (3) 잔여 초 숫자가 `surfaceRaised` 칩(2px `error` 보더) 안에서 한 단계 더 확대, 텍스트는 여전히 `inkPrimary`(대비 ≈11:1 — `error` 텍스트 직접 사용 금지, § Colors 참고), (4) 화면 가장자리에 `error` 톤 비네트가 같은 박자로 맥동 — 풀스크린 플래시가 아니라 테두리만 번지는 수준으로 절제(광과민성 안전). 오답 시 즉시 페널티만큼 바가 눈에 보이게 훅 줄어들고, `-3` 표시도 동일한 칩(흰 배경 + `error` 보더 + `inkPrimary` 텍스트) 형태로 바 옆에서 위로 짧게 떠올랐다 사라짐(재화 카운트업의 반대 방향 피드백).
- **Currency badge** — `pill`, `currencyGold` 아이콘 + `numeric` 폰트 텍스트, 헤더 우측 고정. 재화 획득 시 카운트업 애니메이션.
- **Capsule (뽑기 오픈, 아이템/결과카드 공용)** — `accent` 톤의 캡슐/상자 일러스트, 탭 시 흔들림 → 오픈 → 바운스 리빌 시퀀스, 스킵 불가. 아이템 뽑기와 결과 카드 리빌이 동일한 안무를 공유한다 — 결과 카드 상위 티어(치타급/매급)에서만 `legendarySparkle` 파티클 오버레이 추가.
- **Item icon (기능성 아이템)** `[NEW 2026-07-19]` — 3종 고정(시간 회복/미스매치 방패/재화 2배, `[RENAMED 2026-07-22]` "오답 무효화" → "미스매치 방패" — 일러스트가 이미 방패를 든 고슴도치였던 것과 이름을 맞춤, § Decision Log 2026-07-22), 가벼운 동물 모티프 일러스트(예: 시계를 든 다람쥐, 방패를 든 고슴도치, 동전을 든 너구리) — 순수 픽토그램이 아니라 기존 동물 일러스트 언어를 소모품에도 이어간다. `rounded/sm` 배경 칩 위에 얹는다.
- **Result card (결과/티어 카드)** `[NEW 2026-07-19]` — Capsule과 동일한 리빌 안무(흔들림→오픈→바운스)를 공유하는 전용 카드. 티어 등급 텍스트는 `display` 폰트 700, 등급 배지는 `pill`. 나무늘보급~여우급은 `accent` 톤 배지, 치타급/매급만 `legendarySparkle` 파티클 + 배지.
- **Segment control (뽑기/인벤토리)** `[NEW 2026-07-19]` — 뽑기 화면 상단, 2개 세그먼트를 가로로 붙인 `pill` 컨테이너. 액티브 세그먼트는 `accent` 배경 + `surfaceRaised` 텍스트, 비활성은 투명 배경 + `inkSecondary` 텍스트. 탭 한 번으로 전체 화면 콘텐츠 전환(별도 페이지 이동 아님).
- **Bottom nav tab** `[REMOVED 2026-07-20]` — 2탭(퍼즐/뽑기) 상시 탭바는 완전히 제거됐다. 타이머가 도는 스테이지 중에도 자유롭게 뽑기 화면으로 전환할 수 있었는데, 타이머가 화면 전환과 무관하게 계속 흐르는 구조라 "보이지 않는 동안 시간이 새는" 문제가 있었다(§ Decision Log 2026-07-20). 이 토큰과 관련 모든 참조를 제거 — 뽑기는 아래 Stage-clear dialog 분기로만 진입.
- **Ad banner slot** — `surfaceRaised` 배경의 고정 하단 컨테이너, 상단에 작은 "광고" 라벨 필수(오인 방지, 플랫폼 정책 및 사용자 신뢰 양쪽 이유). 게임 스킨 라운딩 규칙 미적용.
- **Splash screen** `[NEW 2026-07-20]` — 콜드 오픈 최초 화면. `surfaceBase` 배경 중앙에 `primary` 필 원형 엠블럼(로고, 112px) → `display` 폰트 타이틀(28px, 700) → `inkSecondary` 태그라인 순서로 세로 정렬. 하단에 `accent` 톤 로딩 점 3개(순차 점멸)로 백그라운드 초기화 진행을 은은하게 알린다. 새 색/도형 토큰 없이 기존 팔레트만 재사용 — 이 앱의 "첫인상"이 브랜드 톤에서 벗어나지 않게 하려는 의도.
- **Item tray button** `[NEW 2026-07-20]` — 퍼즐 헤더에 상시 노출되는 아이콘 pill(🎒) + `accentLight` 배경의 보유 개수 배지. 탭하면 화면 전환 없이 하단에서 시트가 올라와(`rounded/md` 상단 모서리만) 보유 아이템 목록과 "사용" 버튼을 보여준다 — 타이머가 도는 중에도 안전하게 쓸 수 있는 유일한 아이템 접근 경로(스테이지 클리어 다이얼로그/뽑기 화면과 달리 여기선 타이머를 멈추지 않는다, 의도적 게임 중 상호작용).
- **Stage-clear dialog** `[NEW 2026-07-20]` — 기존 단일 "계속하기" 대신 두 개의 CTA로 분기: `primary` 필 "다음 스테이지"(상단), `accent` 필 "뽑으러 가기 🎁"(그 아래). 결과 카드 링크는 텍스트 버튼으로 그 아래 유지. 어느 쪽을 골라도 다음 스테이지의 타이머는 이 다이얼로그가 떠 있는 동안 시작하지 않는다 — 플레이어가 실제로 다음 스테이지 화면(또는 뽑기 화면 하단 Continue bar)에 진입하는 순간에만 카운트다운이 시작된다.
- **Continue bar** `[NEW 2026-07-20]` — 뽑기 화면 하단 고정, 전체 폭 `primary` 필 버튼("다음 스테이지 시작하기"). 제거된 하단 탭바의 자리를 대신하는, 뽑기 화면의 유일한 탈출구 — 탭하는 순간 퍼즐 화면으로 돌아가며 다음 스테이지 타이머가 시작된다.

## Do's and Don'ts

| Do | Don't |
|---|---|
| 옐로우 배경엔 항상 진한(`inkPrimary`) 텍스트 | 옐로우 배경에 흰 텍스트 |
| 매칭 판별은 아이콘 형태로 | 매칭 판별을 색상에만 의존 |
| 모달은 한 겹까지만 | 다이얼로그 위에 다이얼로그 쌓기 |
| "두뇌 자극", "두뇌 운동" 등 체험 중심 카피 | "치매예방", "인지능력 개선" 등 효능 주장 |
| 광고 슬롯에 "광고" 라벨 명시 | 광고를 게임 UI처럼 위장 |
| `legendarySparkle`는 결과 카드 상위 티어(치타급/매급)에만 | 저채도 포인트 컬러를 장식용으로 남발 |
| 순수 레드 대신 `error`(코랄) 사용 | 경고/의료 앱처럼 읽히는 순수 레드 |
| 타이머는 임계 구간(잔여 25% 이하)에서만 `error` 펄스 | 평상시부터 타이머를 위협적으로 물들이기 |
| 아이템 아이콘도 동물 일러스트 언어 유지 | 아이템만 이질적인 픽토그램/기능 아이콘으로 처리 |
| 임계 구간 비네트는 화면 가장자리만 은은하게 맥동 | 화면 전체를 붉게 깜빡이는 풀스크린 플래시(광과민성 위험) |
| 스테이지 진행 정보는 숫자 텍스트로만("스테이지 8") | 매칭 진행률을 별도 게이지로 시각화(짝맞추기엔 무의미, Timer bar와 시각적 경쟁만 유발) |
| `error`는 배경·보더·아이콘 색으로만 | `error`를 텍스트 글리프 색으로 직접 사용(대비 ≈2.65:1, AA 미달) |
| 탭 액티브 상태는 색 + 배경 칩으로 이중 신호 | 탭 액티브/비활성을 `accent` vs `inkSecondary` 색상 차이로만 구분 |
| `[NEW 2026-07-20]` 뽑기 접근은 타이머가 없는 구간(스테이지 클리어 분기)에서만 | 타이머가 도는 스테이지 중 자유 탐색으로 뽑기 화면에 들어가게 두기(§ Decision Log 2026-07-20) |
