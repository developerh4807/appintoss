# EXPERIENCE.md — 패턴매칭 두뇌자극 + 동물 가챠 수집 게임

## Foundation

앱인토스 미니앱, `@apps-in-toss/web-framework` 기반 WebView 단일 화면 모바일, 세로 모드, 터치 전용 입력. `[ASSUMPTION]` 가로 모드는 지원하지 않는다 — 7일 스코프 안에서 폼팩터를 하나로 고정. TDS(`@toss/tds-mobile`) 컴포넌트(`Top`, `Button`, `Dialog`, `Asset` 등)를 구조적 셸로 유지하되, 색/타이포/도형 토큰은 `DESIGN.md`로 오버라이드한다 — 비주얼 아이덴티티는 TDS가 아니라 `DESIGN.md`가 기준이다.

`[NOTE FOR DEV]` 현재 `src/App.tsx`는 `useState` 기반 단일 페이지 스위처이고, 하단 3탭 네비게이션은 아직 구현되어 있지 않다 — 아래 Information Architecture는 목표 상태이고, 구현은 별도 스토리로 필요하다. `InAppAdsPage`는 개발자센터 스캐폴드 테스트 화면으로 보이며, 최종 IA에는 포함되지 않는다 — 프로덕션 진입 전 홈 화면에서 제거 확인 필요.

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 퍼즐 (홈) | 앱 콜드 오픈, 하단 탭 | 패턴매칭 퍼즐 플레이, 스테이지 클리어 → 재화 획득 |
| 뽑기 | 하단 탭 | 재화 소모 또는 보상형 광고 시청으로 동물 캐릭터 뽑기 |
| 도감 | 하단 탭 | 수집한 동물 캐릭터 목록, 공유 진입점 |
| 온보딩 (첫 실행) | 콜드 오픈, 최초 1회만 | 첫 클리어 → 첫 뽑기 유도 (UJ-1) |
| 공유 시트 | 도감 상단 버튼 | 네이티브 공유 시트 — 화면이 아니라 모달 오버레이 |

하단 탭 3개(퍼즐/뽑기/도감) 고정, 서랍/햄버거 없음. 모달은 한 겹까지만(§ DESIGN.md Layout & Spacing) — 클리어 다이얼로그, 뽑기 결과, 공유 시트가 동시에 쌓이는 일은 없다.

→ 구성 레퍼런스: [mockups/key-puzzle-main.html](mockups/key-puzzle-main.html) (퍼즐 대기/클리어 다이얼로그), [mockups/key-gacha.html](mockups/key-gacha.html) (뽑기 대기/리빌 클라이맥스), [mockups/key-collection.html](mockups/key-collection.html) (도감). 스펀 문서(이 파일과 DESIGN.md)가 목업과 충돌하면 스펀이 이긴다.

## Voice and Tone

브랜드 톤/미학은 `DESIGN.md.Brand & Style` 참고. 여기는 실제 카피 규칙만 다룬다 — PRD § Constraints and Guardrails의 법적 가드레일을 그대로 승계한다.

| Do | Don't |
|---|---|
| "두뇌를 톡톡 자극해봐요" | "치매 예방에 도움이 돼요" |
| "패턴을 맞추는 즐거움" | "인지능력을 개선해요" |
| "재화 10개 획득!" | "포인트 10P 적립" (앱인토스 정책상 "포인트" 단어 자체 금지, PRD §3) |
| "광고 보고 무료로 뽑기" (명시적 고지) | 보상형 광고를 "보너스 기회"처럼 출처를 흐려 표현 |
| 짧고 밝은 감탄형 카피 | 성취/경쟁을 압박하는 카피("놓치면 손해예요" 류) |

## Component Patterns

행동 규칙만 다룬다. 비주얼 스펙은 `DESIGN.md.Components` 참고.

| Component | Use | Behavioral rules |
|---|---|---|
| Tile | 퍼즐 그리드 | 탭하면 선택(최대 2개 동시 선택). 매칭 시 페이드아웃 제거. 불일치 시 500ms 후 자동 리셋(기존 `PuzzlePage.tsx` `MISMATCH_DELAY_MS` 그대로 유지) — 그 동안 다른 타일 탭 무시. |
| Progress bar | 퍼즐 헤더 | 현재 스테이지 클리어 진행률만 표시, 다음 스테이지 예고 없음(서프라이즈 유지). |
| Currency badge | 전 화면 헤더 | 재화 증감 시 숫자 카운트업(≥300ms), 즉시 스냅 금지 — 획득감을 눈으로 확인시킨다. |
| Capsule (뽑기) | 뽑기 화면 | 탭 → 흔들림 → 오픈 → 캐릭터 리빌 순서 고정, 스킵 불가(이 프로젝트의 감정적 클라이맥스이므로 생략 옵션 없음). Reduce Motion 시에만 흔들림 단계 축소. |
| Bottom nav tab | 전 화면 | 탭 전환 시 스크롤 위치 초기화하지 않음(재방문 시 이전 위치 유지) — 도감을 스크롤하다 퍼즐로 갔다 와도 도감 위치 보존. |
| Ad banner slot | 퍼즐/도감 화면 | 상시 노출(FR-7), 콘텐츠와 함께 스크롤되지 않고 하단 고정. 토스앱 5.241.0 미만에서는 슬롯 자체를 렌더링하지 않는다(PRD §4.3 NFR). |
| Share button | 도감 상단 | 탭 → `getTossShareLink` 또는 기본 공유 시트(§7 Platform 확정 시 결정) 호출. 초대 성공 보상 없음(v1은 순수 공유만, `contactsViral`은 v2). |

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 최초 보드 생성 | 퍼즐 | 스켈레톤 없이 즉시 렌더(연산 가벼움, 로딩 상태 불필요로 가정 `[ASSUMPTION]`) |
| 스테이지 클리어 | 퍼즐 | 다이얼로그: "스테이지 클리어! 재화 N개 획득" → 확인 시 다음 스테이지 자동 진입 |
| 재화 부족 (뽑기 시도) | 뽑기 | 뽑기 버튼 비활성 대신, 탭 시 "재화가 부족해요 — 광고 보고 무료로 뽑아볼까요?" 다이얼로그로 보상형 광고 유도(이탈 대신 전환 기회로 전환, PRD §4.2 원칙) |
| 광고 로드 실패 | 뽑기, 배너 | 배너: 슬롯을 조용히 비움(빈 자리 노출 안 함). 보상형: "지금은 광고를 불러올 수 없어요, 잠시 후 다시 시도해주세요" 토스트, 재화 소모 경로는 항상 대체 옵션으로 유지 |
| 도감 빈 상태 (최초) | 도감 | "아직 모은 친구가 없어요 — 첫 뽑기를 해볼까요?" + 뽑기 화면 링크 |
| 도감 미획득 항목 | 도감 | 실루엣/그레이스케일 처리, 이름 비공개("???") — 수집 욕구 자극 |
| 하위 토스앱 버전 | 퍼즐/도감 | 배너 광고 슬롯 자체를 렌더링하지 않음(공백 유지, 대체 콘텐츠로 채우지 않음) |
| 온보딩 완료 후 재방문 | 퍼즐 | 온보딩 오버레이 재노출 안 함(로컬 플래그로 1회성 관리) `[ASSUMPTION]` |

## Interaction Primitives

- 탭으로만 조작 — 스와이프/드래그/롱프레스 없음. 30-50대+ 타겟에게 발견성이 낮은 제스처는 배제.
- 뽑기 캡슐은 탭 1회로 전체 시퀀스 시작, 중간에 탭해도 스킵되지 않음(클라이맥스 보호).
- 타이머·카운트다운 기반 압박 요소 전면 금지 — "맞추는 즐거움" 원칙과 정면 충돌.
- **Banned**: 캐러셀, 배지 카운트(빨간 점 알림), 스트릭/연속 출석 압박, 강제 튜토리얼 스킵 불가 오버레이.

## HUD & Diegetic UI

전투형 실시간 HUD가 없는 캐주얼 퍼즐이라 오버레이가 단순하다. **Non-diegetic**: 헤더의 스테이지 진행바 + 재화 배지 — 항상 떠 있는 유일한 상시 오버레이. **Diegetic에 가까운 요소**: 매칭 그리드의 타일 자체(게임 월드가 곧 UI), 뽑기 캡슐(월드 오브젝트처럼 반응). 정보 위계: 재화/스테이지는 항상 최우선 가시성, 광고 슬롯은 항상 노출되지만 시선 하이어라키상 최하단(콘텐츠를 가리지 않음).

## Input Schemes

- **터치 단일 스킴** — 탭이 유일한 입력. 리매핑 대상 없음(액션이 탭 하나뿐).
- 컨텍스트 민감 프롬프트 해당 없음(디바이스별 버튼 글리프 스왑 불필요 — 단일 플랫폼, 단일 입력 방식).

## Game Feel & Juice

매칭 성공 시 타일이 `{colors.success}`로 짧게 플래시된 뒤 스케일업하며 페이드아웃, 가벼운 경쾌한 효과음(의료/경고 느낌 배제). 불일치 시 타일이 `{colors.error}`로 500ms 플래시 + 살짝 좌우 흔들림(기존 코드 타이밍 유지). 스테이지 클리어 시 재화 배지가 카운트업하며 `{colors.currencyGold}`로 잠깐 강조. 뽑기 캡슐 오픈은 이 프로젝트에서 감정적으로 가장 중요한 순간 — 흔들림(서스펜스) → 오픈 → 캐릭터 바운스 등장, 레어 등급이면 `{colors.legendarySparkle}` 파티클 + 별도 사운드. **Reduce Motion**: 흔들림/바운스 단계를 축소하되 결과 리빌 자체는 생략하지 않음(감정적 클라이맥스는 유지, 움직임만 줄인다).

## Accessibility Floor

시각적 대비는 `DESIGN.md`에서 다룬다. 여기는 행동 규칙:

- 탭 타겟 48px 이상, 본문 폰트 16px 이상 — Commercial 스테이크 + 30-50대+ 타겟에 맞춘 넉넉한 베이스라인(§ Decision Log 참고).
- 매칭 판별은 아이콘 형태로만 — 색상 단독 신호 금지(색맹 안전, `DESIGN.md.Colors` 규칙과 연동).
- 광고(배너/보상형) 진입 전 항상 "광고" 명시 라벨 — 오인 방지.
- 다이얼로그·토스트·상태 변화에 스크린리더 라벨 부여 `[ASSUMPTION: 상세 ARIA/접근성 트리 설계는 구현 단계에서 확정]`.
- Reduce Motion 토글 시 뽑기 연출 등 모든 애니메이션이 최소화 모드로 전환.

## Inspiration & Anti-patterns

- **Lifted from 애니팡류 캐주얼 매칭**: 즉각적 피드백, 짧은 세션 단위, 낮은 학습 곡선.
- **Lifted from "돈버는 수족관" 사례** (PRD §4.3 근거): 광고를 별도 화면이 아니라 코어 루프의 감정 곡선(뽑기 직전 충동 정점)에 얹는 배치.
- **Rejected — 캔디크러시식 과포화 이펙트/타이머 압박**: 30-50대+ 타겟에게 피로감을 유발하고, "가볍게 두뇌를 자극" JTBD와 어긋남.
- **Rejected — 두뇌 트레이닝 클리닉 톤**(중립 그레이, 클리니컬 아이콘): 법적 가드레일(치매예방 등 효능 주장 금지)과 정면 충돌하는 인상을 줄 위험.

## Responsive & Platform

- 세로 모드 고정, 토스 인앱 웹뷰(주소창 없음) — 상단 세이프에어리어는 토스 자체 네비게이션 바를 고려해 확보.
- 작은 화면 기기에서도 매칭 그리드 열 수(3~4열, 기존 `columns` 로직)가 유지되도록 최소 타일 크기를 확보 — 타일이 48px 탭 타겟 미만으로 줄어들면 열 수를 낮춘다.
- 다크모드는 v1 스코프 밖 `[ASSUMPTION]` — PRD §11 counter-metric("완성도를 높이기 위해 출시를 늦추는 것")에 근거한 의도적 스코프컷. v2 후보.

## Key Flows

### Flow 1 — 미영(52세)이 첫 실행에서 첫 캐릭터를 뽑는다 (UJ-1)

미영은 딸이 카톡으로 링크를 보내줘서 처음 앱을 켠다.

1. 콜드 오픈 → 온보딩 오버레이: 패턴매칭 규칙을 한 화면으로 짧게 안내(스킵 불가하지 않되, 텍스트는 최소).
2. 첫 스테이지 진입 — 난이도는 PRD 원칙대로 낮게, 실패 없이 클리어 가능한 수준.
3. 타일을 탭해 짝을 맞춘다 — 맞을 때마다 `{colors.success}` 플래시로 즉각 확인.
4. 마지막 타일 쌍을 맞추자 클리어 다이얼로그: "스테이지 클리어! 재화 10개 획득."
5. 재화 배지가 카운트업하며 채워진다.
6. 자연스럽게 뽑기 탭으로 유도(다이얼로그 내 "뽑으러 가기" 버튼).
7. **Climax**: 뽑기 캡슐을 탭 — 흔들림 → 오픈 → 첫 동물 캐릭터 등장. 도감에 첫 항목이 채워진다.

실패 상황: 온보딩 중 이탈 → 다음 콜드 오픈 시 온보딩부터 재시작하지 않고 퍼즐 화면으로 바로 진입(재방문 마찰 최소화) `[ASSUMPTION]`.

### Flow 2 — 재방문 유저의 일일 리텐션 루프 (UJ-2)

3일째 앱을 켠 유저가 출근 전 자투리 시간에 들른다.

1. 콜드 오픈 → 퍼즐 화면, 이전에 멈춘 스테이지부터 이어서.
2. 2~3개 스테이지를 가볍게 클리어 — 각 클리어마다 재화 획득 피드백.
3. 도감 탭으로 이동해 지금까지 모은 캐릭터 확인 — 빈 칸(미획득 실루엣)이 다음 목표가 된다.
4. **Climax**: 모은 재화로 뽑기를 시도해 새 캐릭터를 획득, 도감의 빈 칸 하나가 채워진다 — "오늘도 뭔가 채웠다"는 확인.

### Flow 3 — 보상형 광고로 무료 뽑기 기회를 얻는다 (UJ-3)

재화가 부족한 유저가 뽑기 화면에서 막힌다.

1. 뽑기 화면에서 재화 부족 상태로 뽑기 버튼 탭.
2. "재화가 부족해요 — 광고 보고 무료로 뽑아볼까요?" 다이얼로그.
3. 광고 시청 선택 → 보상형 광고 재생(플랫폼 SDK).
4. 시청 완료 → 무료 뽑기 1회 즉시 지급, 캡슐 오픈 시퀀스로 자연스럽게 연결.
5. **Climax**: 광고를 봤다는 "손해" 느낌 없이 바로 캡슐이 열리며 보상으로 전환 — 대기 없는 즉시 연결이 핵심.

실패 상황: 광고 로드 실패 → "지금은 광고를 불러올 수 없어요" 토스트, 재화 획득 경로(퍼즐 클리어)로 자연스럽게 유도.

### Flow 4 — 자녀가 부모님께 공유한다 (UJ-4, 최소 버전)

`[NOTE FOR PM]` PRD §4.4에 명시된 대로, 이 v1 흐름은 브리프가 의도한 "리퍼럴 성장 루프"를 온전히 구현하지 않는다 — 아래는 최소 공유 버튼 범위.

1. 도감 화면에서 공유 버튼 탭.
2. 네이티브 공유 시트(또는 `getTossShareLink`) 노출 — 단순 링크/이미지 공유.
3. 카카오톡 등으로 부모님께 전송.
4. **Climax**: 딸이 "이거 봐, 이 동물 귀엽지" 하고 자연스럽게 공유 — 초대 성공에 대한 보상은 없음(v2 후보).

빈 상태: 도감이 비어 있으면 공유 버튼은 노출하되 공유 콘텐츠는 앱 소개 링크로 대체 `[ASSUMPTION]`.
