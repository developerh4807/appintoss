# EXPERIENCE.md — 패턴매칭 두뇌자극 + 제한시간 압박 + 기능성 아이템 뽑기 게임

## Foundation

앱인토스 미니앱, `@apps-in-toss/web-framework` 기반 WebView 단일 화면 모바일, 세로 모드, 터치 전용 입력. `[ASSUMPTION]` 가로 모드는 지원하지 않는다 — 짧은 개발 스코프 안에서 폼팩터를 하나로 고정. TDS(`@toss/tds-mobile`) 컴포넌트(`Top`, `Button`, `Dialog`, `Asset` 등)를 구조적 셸로 유지하되, 색/타이포/도형 토큰은 `DESIGN.md`로 오버라이드한다 — 비주얼 아이덴티티는 TDS가 아니라 `DESIGN.md`가 기준이다.

`[NOTE FOR DEV]` 현재 `src/App.tsx`는 `useState` 기반 단일 페이지 스위처이고, 하단 탭 네비게이션은 아직 구현되어 있지 않다(2026-07-19 재확인 — 변화 없음). `src/pages/PuzzlePage.tsx`에도 아직 제한시간/카운트다운 로직은 없다(`MISMATCH_DELAY_MS` 500ms 리셋 딜레이만 존재) — 아래 Information Architecture와 제한시간 관련 서술은 전부 목표 상태이며, 구현은 별도 스토리로 필요하다. `InAppAdsPage`는 개발자센터 스캐폴드 테스트 화면으로 보이며, 최종 IA에는 포함되지 않는다 — 프로덕션 진입 전 홈 화면에서 제거 확인 필요.

`[UPDATED 2026-07-19]` PRD 재작성으로 코어루프가 "압박 없는 매칭"에서 "제한시간 압박 매칭"으로 뒤집혔고, 뽑기 대상이 동물 캐릭터에서 기능성 아이템으로 바뀌었다. 이 문서는 그 개정을 전면 반영한 버전이다 — 색/타이포/접근성 베이스라인 등 `DESIGN.md`의 근본 토큰은 이전 세션에서 유지, 코어루프·IA·컴포넌트·플로우만 갱신했다. 변경 이력은 `.decision-log.md` "Update session — 2026-07-19" 참고.

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 퍼즐 (홈) | 앱 콜드 오픈, 하단 탭 | 제한시간 내 패턴매칭 퍼즐 플레이, 클리어 → 재화 획득, 실패 → 광고/재시도 분기 |
| 뽑기 (세그먼트: 뽑기) | 하단 탭, 기본 세그먼트 | 재화 소모 또는 보상형 광고 시청으로 기능성 아이템 뽑기 |
| 인벤토리 (세그먼트: 인벤토리) | 뽑기 화면 상단 세그먼트 전환 | 보유 아이템 확인, 스테이지 시작 전/중 소모 |
| 결과 카드 | 스테이지 클리어 다이얼로그 내 링크, 또는 세션 종료(실패 후 이어하지 않음) 시점 | 동물 티어 리빌, 공유·초대 진입점 (UJ-4) |
| 공유 시트 | 결과 카드 내 버튼 | 네이티브 공유 시트(또는 `getTossShareLink`) — 화면이 아니라 모달 오버레이 |
| `[UPDATED]` 첫 실행 학습 구간 | 콜드 오픈 직후, 강제 온보딩 화면 없음 | 스테이지 1~3의 완화된 고정 제한시간(그레이스 구간)이 암묵적 학습 역할, 첫 아이템 획득 시 1회성 컨텍스트 툴팁 (UJ-1, FR-9) |

`[UPDATED 2026-07-19]` 하단 탭 2개(퍼즐/뽑기) 고정, 서랍/햄버거 없음 — 도감 탭은 캐릭터 수집 시스템 폐기와 함께 제거, 인벤토리는 뽑기 화면 상단 Segment control(뽑기 | 인벤토리)로 흡수했다. 모달은 한 겹까지만(§ DESIGN.md Layout & Spacing) — 클리어 다이얼로그, 뽑기/결과 리빌, 공유 시트가 동시에 쌓이는 일은 없다.

`[REMOVED 2026-07-19]` 별도 온보딩 오버레이 화면 — PRD FR-9가 강제 스킵 불가 튜토리얼을 명시적 Non-goal로 못박으면서, 암묵적 학습 구간(그레이스 타이머)과 최초 아이템 획득 시 1회성 툴팁으로 대체됐다. 이는 예전 `EXPERIENCE.md`의 "스킵 불가능한 강제 튜토리얼 금지" 원칙과 원래 일치하던 방향이라 충돌 아님(PRD §0 참고).

## Voice and Tone

브랜드 톤/미학은 `DESIGN.md.Brand & Style` 참고. 여기는 실제 카피 규칙만 다룬다 — PRD § Constraints and Guardrails의 법적 가드레일을 그대로 승계한다.

| Do | Don't |
|---|---|
| "두뇌를 톡톡 자극해봐요" | "치매 예방에 도움이 돼요" |
| "패턴을 맞추는 즐거움" | "인지능력을 개선해요" |
| "재화 10개 획득!" | "포인트 10P 적립" (앱인토스 정책상 "포인트" 단어 자체 금지, PRD §3) |
| "광고 보고 무료로 뽑기" (명시적 고지) | 보상형 광고를 "보너스 기회"처럼 출처를 흐려 표현 |
| 짧고 밝은 감탄형 카피 | 성취/경쟁을 압박하는 카피("놓치면 손해예요" 류) |
| `[NEW 2026-07-19]` "반응속도 치타급!", "이번 판 기록" | "당신의 반응속도는 OO세", "측정/검사/진단" 같은 평가·나이환산 함의 표현 (PRD §4.4, §10 — Brain Age/Lumosity 패턴 회피) |
| `[NEW 2026-07-19]` "시간이 얼마 안 남았어요!" (임계 구간 진입 시 가벼운 리듬감) | "실패하면 처음부터예요" 같은 손실 강조형 위협 카피 |

## Component Patterns

행동 규칙만 다룬다. 비주얼 스펙은 `DESIGN.md.Components` 참고.

| Component | Use | Behavioral rules |
|---|---|---|
| Tile | 퍼즐 그리드 | 탭하면 선택(최대 2개 동시 선택). 매칭 시 페이드아웃 제거. 불일치 시 500ms 후 자동 리셋(기존 `PuzzlePage.tsx` `MISMATCH_DELAY_MS` 그대로 유지) — 그 동안 다른 타일 탭 무시. 오답 확정 순간 Timer bar에 즉시 페널티 반영(FR-5). |
| Timer bar | 퍼즐 헤더 | `[UPDATED 2026-07-19]` 헤더의 시각적 주인공(§ DESIGN.md Components) — 스테이지 진입과 동시에 카운트다운 시작(FR-3). 오답 시 즉시 페널티만큼 훅 감소 + `-3` 칩 표시(FR-5). 잔여 25% 이하 진입 시 `error` 펄스 + 글로우 + 화면 가장자리 비네트로 전환, 잔여 초 숫자는 `surfaceRaised`+`error`보더 칩 안에서 확대(텍스트는 `inkPrimary` 유지, `[FIXED 2026-07-19]` — `error` 텍스트는 대비 미달, § DESIGN.md Colors). 0 도달 시 스테이지 실패 다이얼로그로 즉시 전환(FR-6). 스테이지 번호는 이 바 위에 텍스트로만 표시 — 별도 진행 게이지 없음(매칭 게임은 클리어 시 항상 100%라 진행률 시각화가 무의미하다는 사용자 판단, 2026-07-19). |
| Currency badge | 전 화면 헤더 | 재화 증감 시 숫자 카운트업(≥300ms), 즉시 스냅 금지 — 획득감을 눈으로 확인시킨다. |
| Capsule (아이템 뽑기) | 뽑기 세그먼트 | 탭 → 흔들림 → 오픈 → 아이템 리빌 순서 고정, 스킵 불가(이 프로젝트의 감정적 클라이맥스이므로 생략 옵션 없음). Reduce Motion 시에만 흔들림 단계 축소. `[UPDATED 2026-07-19]` 리빌 대상이 동물 캐릭터 → 기능성 아이템 3종(FR-12)으로 변경. |
| Segment control (뽑기/인벤토리) | 뽑기 화면 상단 | `[NEW 2026-07-19]` 탭 시 화면 콘텐츠 전체 전환(페이지 이동 아님), 전환 시 스크롤 위치는 세그먼트별로 독립 보존. |
| Inventory item row | 인벤토리 세그먼트 | `[NEW 2026-07-19]` 보유 아이템 탭 → "지금 사용" 또는 "다음 스테이지 시작 시 사용" 선택(스테이지 중/전 소모 모두 허용, FR-13). 소모 즉시 효과 적용 확인 토스트. |
| Result card (결과 카드) | 클리어 다이얼로그 내 링크 / 세션 종료 | `[NEW 2026-07-19]` Capsule과 동일한 리빌 안무 공유, 스킵 불가. 도달 스테이지 기준 티어 판정(FR-18, `addendum.md` 초안 구간). |
| Bottom nav tab | 전 화면 | 탭 전환 시 스크롤 위치 초기화하지 않음(재방문 시 이전 위치 유지). `[UPDATED 2026-07-19]` 2탭(퍼즐/뽑기)로 축소 — 도감 탭 제거. |
| Ad banner slot | 퍼즐/뽑기 화면 | 상시 노출(FR-14), 콘텐츠와 함께 스크롤되지 않고 하단 고정. 토스앱 5.241.0 미만에서는 슬롯 자체를 렌더링하지 않는다(PRD §4.3 NFR). |
| Retry counter | 스테이지 실패 다이얼로그 | `[NEW 2026-07-19]` 동일 스테이지 연속 무료 재시도 횟수 표시(최대 2회, FR-7). 3회차부터 무료 재시도 버튼 비활성 + 광고 시청 버튼만 강조. 다른 스테이지 진행/앱 재시작 시 카운트 리셋. |
| Share button | 결과 카드 내 | 탭 → `getTossShareLink` 또는 기본 공유 시트 호출(FR-19), 미니앱 승인 여부와 무관하게 항상 노출. |
| Invite button (`contactsViral`) | 결과 카드 내, Share button 옆 | `[NEW 2026-07-19]` 미니앱 승인 완료 전에는 숨김(승인 전 호출 시 Internal Server Error, PRD §4.4 NFR) — 승인 후에만 노출. 토스앱 5.223.0 미만에서도 숨김(호출 결과 `undefined`). 탭 → 연락처 선택 → 초대 발송 → 성공 시 아이템 뽑기권 1개 지급(FR-20). |

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 최초 보드 생성 | 퍼즐 | 스켈레톤 없이 즉시 렌더(연산 가벼움, 로딩 상태 불필요로 가정 `[ASSUMPTION]`) |
| 스테이지 클리어 | 퍼즐 | 다이얼로그: "스테이지 클리어! 재화 N개 획득" → 확인 시 다음 스테이지 자동 진입. 개인 최고 기록 경신 시 다이얼로그 안에 짧은 축하 배지 추가(FR-8). |
| `[NEW 2026-07-19]` 타이머 임계 진입 | 퍼즐 | 잔여 25% 이하: Timer bar `error` 펄스 전환, 잔여 초 숫자 확대 + `error` 색. 사운드는 은은한 틱 정도(경고음 아님 — 의료/경고 톤 회피 원칙 승계). |
| `[NEW 2026-07-19]` 스테이지 실패 (타이머 0) | 퍼즐 | 다이얼로그: "시간이 다 됐어요! 광고 보고 이어할까요?" + 무료 재시도 버튼(Retry counter 표시, FR-7) + 광고 시청 버튼(FR-17). 3회차 연속 실패부터 무료 재시도 버튼 비활성. |
| 재화 부족 (뽑기 시도) | 뽑기 | 뽑기 버튼 비활성 대신, 탭 시 "재화가 부족해요 — 광고 보고 무료로 뽑아볼까요?" 다이얼로그로 보상형 광고 유도(이탈 대신 전환 기회로 전환, PRD §4.2 원칙) |
| 광고 로드 실패 | 뽑기, 퍼즐 실패 다이얼로그, 배너 | 배너: 슬롯을 조용히 비움(빈 자리 노출 안 함). 보상형: "지금은 광고를 불러올 수 없어요, 잠시 후 다시 시도해주세요" 토스트, 대체 경로(재화 소모 뽑기, 무료 재시도)는 항상 유지. |
| `[UPDATED 2026-07-19]` 인벤토리 빈 상태 (최초) | 인벤토리 세그먼트 | "아직 보유한 아이템이 없어요 — 뽑기로 얻어볼까요?" + 뽑기 세그먼트 링크. 예전 도감 빈 상태 카피를 대체. |
| 하위 토스앱 버전 | 퍼즐/뽑기 | 배너 광고 슬롯 자체를 렌더링하지 않음(공백 유지, 대체 콘텐츠로 채우지 않음). `contactsViral` 관련 UI(초대 버튼)도 5.223.0 미만에서 숨김. |
| `[UPDATED 2026-07-19]` 첫 아이템 획득 | 인벤토리 진입 첫 순간 | 1회성 컨텍스트 툴팁으로 아이템 소모 방법 설명(FR-9) — 그 전까지 아이템 UI 자체를 전면에 노출하지 않는다. 로컬 플래그로 1회 관리 `[ASSUMPTION]`. |
| `[NEW 2026-07-19]` 미니앱 승인 대기 중 | 결과 카드 | 초대 버튼(FR-20) 숨김, 공유 버튼(FR-19)만 노출 — 단계적 출시(PRD §11). |

## Interaction Primitives

- 탭으로만 조작 — 스와이프/드래그/롱프레스 없음. 30-50대+ 타겟에게 발견성이 낮은 제스처는 배제.
- 뽑기 캡슐/결과 카드는 탭 1회로 전체 시퀀스 시작, 중간에 탭해도 스킵되지 않음(클라이맥스 보호).
- `[REVERSED 2026-07-19]` 타이머·카운트다운 기반 압박 요소는 이제 코어루프의 필수 요소다(PRD §4.1, FR-1~9) — 예전 "타이머 압박 전면 금지" 원칙을 의도적으로 뒤집은 결정(`.decision-log.md` 참고). 다만 무제한으로 압박하지 않는다: 평상시엔 절제된 카운트다운, 임계 구간(잔여 25% 이하)에서만 명확한 위기 신호로 전환 — § DESIGN.md Brand & Style "제한시간 압박과의 공존 원칙" 참고.
- **Banned**: 캐러셀, 배지 카운트(빨간 점 알림), 스트릭/연속 출석 압박, 강제 튜토리얼 스킵 불가 오버레이. `[UPDATED 2026-07-19]` 타이머 압박 자체는 더 이상 금지 목록에 없음 — 위 항목 참고.

## HUD & Diegetic UI

전투형 실시간 HUD는 아니지만, `[UPDATED 2026-07-19]` 제한시간 압박이 코어루프에 들어오며 Timer bar가 이 화면의 사실상 유일한 HUD 요소가 됐다. **Non-diegetic**: 헤더의 Timer bar(스테이지 번호는 그 위 텍스트로만) + 재화 배지 — 항상 떠 있는 상시 오버레이. `[REMOVED 2026-07-19]` 예전엔 여기에 스테이지 진행바도 있었으나, 매칭 게임에서 진행률 시각화가 의미 없다는 판단으로 제거하고 그 시각적 비중을 전부 Timer bar에 넘겼다 — Timer bar는 평상시 절제된 크기·톤이지만 예전 진행바보다 확연히 두꺼워 기본값부터 헤더의 시각적 중심이며, 임계 구간에서는 펄스·글로우·화면 가장자리 비네트까지 더해 대비를 최대로 키운다(§ DESIGN.md). **Diegetic에 가까운 요소**: 매칭 그리드의 타일 자체(게임 월드가 곧 UI), 뽑기 캡슐/결과 카드(월드 오브젝트처럼 반응). 정보 위계: 재화/제한시간은 항상 최우선 가시성, 광고 슬롯은 항상 노출되지만 시선 하이어라키상 최하단(콘텐츠를 가리지 않음).

## Input Schemes

- **터치 단일 스킴** — 탭이 유일한 입력. 리매핑 대상 없음(액션이 탭 하나뿐).
- 컨텍스트 민감 프롬프트 해당 없음(디바이스별 버튼 글리프 스왑 불필요 — 단일 플랫폼, 단일 입력 방식).

## Game Feel & Juice

매칭 성공 시 타일이 `{colors.success}`로 짧게 플래시된 뒤 스케일업하며 페이드아웃, 가벼운 경쾌한 효과음(의료/경고 느낌 배제). 불일치 시 타일이 `{colors.error}`로 500ms 플래시 + 살짝 좌우 흔들림(기존 코드 타이밍 유지), **동시에** `[NEW 2026-07-19]` Timer bar가 페널티만큼 훅 줄어들며 `-3` 플로팅 텍스트가 떠오른다 — 오답의 대가가 타일과 타이머 두 곳에서 동시에 느껴지게 한다. 스테이지 클리어 시 재화 배지가 카운트업하며 `{colors.currencyGold}`로 잠깐 강조.

`[UPDATED 2026-07-19]` 타이머가 임계 구간(잔여 25% 이하)에 들어가면 네 가지가 동시에 켜진다 — 서로 다른 메시지가 아니라 "시간이 얼마 없다" 하나를 색·모션·크기·위치 네 채널로 중복 전달하는 것이다: (1) Timer bar 필이 `{colors.error}`로 전환, (2) 0.6초 반주기 펄스(스케일 1.0→1.04, 전체 주기 ≈0.83Hz) + 은은한 `error` 글로우 확산, (3) 잔여 초 숫자가 `surfaceRaised` 칩(2px `error` 보더) 안에서 한 단계 더 확대되되 텍스트 자체는 `inkPrimary` 유지(`error`를 텍스트 글리프 색으로 쓰면 대비 미달, `[FIXED 2026-07-19]`), (4) 화면 가장자리에 `error` 톤 비네트가 같은 박자로 맥동. 사용자 피드백(2026-07-19)에 따라 급박함을 더 뚜렷하게 키운 조합이지만, 화면 전체를 붉게 깜빡이는 풀스크린 플래시는 광과민성 발작 위험 때문에 의도적으로 배제했다 — 비네트는 테두리에서만 은은하게 번진다(§ DESIGN.md Do's and Don'ts). 오답 페널티 `-3` 표시도 같은 칩 형태(흰 배경 + `error` 보더 + `inkPrimary` 텍스트)를 쓴다. 사운드는 경고음이 아니라 가벼운 틱 정도로 그친다.

뽑기 캡슐/결과 카드 오픈은 이 프로젝트에서 감정적으로 가장 중요한 순간 — 흔들림(서스펜스) → 오픈 → 바운스 등장, `[UPDATED 2026-07-19]` 아이템 뽑기는 등급 없이 담백하게 리빌하고, 결과 카드는 상위 티어(치타급/매급)일 때만 `{colors.legendarySparkle}` 파티클 + 별도 사운드로 강조한다 — 예전엔 "레어 캐릭터"가 이 강조의 트리거였다면, 지금은 "높은 반응속도 티어"가 트리거다.

**Reduce Motion**: 흔들림/바운스/펄스 단계를 축소하되 결과 리빌 자체는 생략하지 않음(감정적 클라이맥스는 유지, 움직임만 줄인다). 타이머 임계 펄스도 Reduce Motion 시 애니메이션 대신 정적인 색 전환 + 숫자 강조만 유지.

## Accessibility Floor

시각적 대비는 `DESIGN.md`에서 다룬다. 여기는 행동 규칙:

- 탭 타겟 48px 이상, 본문 폰트 16px 이상 — Commercial 스테이크 + 30-50대+ 타겟에 맞춘 넉넉한 베이스라인(§ Decision Log 참고).
- 매칭 판별은 아이콘 형태로만 — 색상 단독 신호 금지(색맹 안전, `DESIGN.md.Colors` 규칙과 연동).
- `[NEW 2026-07-19]` 타이머 임계 상태도 색상 단독 신호 금지 원칙을 따른다 — `error` 색 전환과 동시에 잔여 초 숫자 확대, 펄스 모션(또는 Reduce Motion 시 정적 강조)까지 함께 켜서 색맹/저시력 유저도 위기 상태를 인지할 수 있게 한다.
- `[FIXED 2026-07-19]` 하단 탭 액티브 상태도 색상 단독 신호였다(`review-accessibility.md` medium 발견) — 액티브 탭은 `accentLight` 배경 칩을 추가해 색만이 아니라 형태로도 구분되게 한다(§ DESIGN.md Components).
- `[NEW 2026-07-19]` 임계 구간 비네트·펄스는 광과민성 발작 유발 기준에 걸리지 않도록 (a) 화면 전체가 아니라 가장자리만 맥동하고, (b) 펄스 전체 주기 ≈1.2초(≈0.83Hz)로 WCAG 2.3.1의 3Hz 기준에 여유 있게 못 미치게 유지한다 — 화면 전체를 붉게 깜빡이는 방식은 애초에 채택하지 않는다.
- `[FIXED 2026-07-19]` `error`(#FF6B5C)는 `surfaceBase` 위에서 텍스트 색으로 쓰면 ≈2.65:1로 WCAG AA 미달이다(`review-accessibility.md` critical 발견) — 임계 구간 잔여 초 숫자·오답 페널티 `-3` 표시는 `error`를 텍스트가 아니라 칩 보더/배경으로만 쓰고 텍스트는 `inkPrimary`를 유지한다(§ DESIGN.md Colors).
- 광고(배너/보상형) 진입 전 항상 "광고" 명시 라벨 — 오인 방지.
- `[UPDATED 2026-07-19]` 다이얼로그·토스트·상태 변화에 스크린리더 라벨 부여. 타이머는 이제 코어루프라 매초 안내는 스팸이 되고 침묵은 실패로 이어진다 — 최소 기준으로 `aria-live="assertive"` 안내를 **임계 구간 진입 시 1회**, **스테이지 실패 시 1회**만 발화한다(매초 안내 금지). 세부 ARIA 트리 설계는 구현 단계에서 확정 `[ASSUMPTION]`이지만, 안내 시점/빈도 정책 자체는 이 스펙에서 확정한다(`review-accessibility.md` high 발견 — "구현 단계에서 확정"으로 통째로 미루는 건 스펙 공백이라는 지적 반영).
- Reduce Motion 토글 시 뽑기/결과 카드 연출, 타이머 펄스 등 모든 애니메이션이 최소화 모드로 전환.
- `[OPEN — NOTE FOR PM, 2026-07-19]` **WCAG 2.2.1(Timing Adjustable) 갭**: 이 게임의 코어루프는 되돌릴 수 없는 하드 타이머다. 광고 시청/무료 재시도(FR-7, FR-17)는 실패 *이후* 구제일 뿐, 진행 중인 스테이지 자체의 시간을 늘려주는 수단이 아니다 — 손 떨림·저시력·연령대 처리속도 저하 등으로 구조적으로 더 많은 시간이 필요한 유저에게는 지금 스펙에 실질적 보완책이 없다(`review-accessibility.md` critical 발견). 두 방향이 있다: (a) 재화와 무관하게 상시 켤 수 있는 "여유 모드"(기본 제한시간 완화 또는 임계 구간 비활성) 같은 별도 접근성 수단을 추가하거나, (b) 제한시간이 이 게임의 핵심 정체성이라는 근거로 WCAG의 essential-exception을 의도적으로 원용하고 그 판단을 문서화한다. 이 결정은 PRD의 "추가 시스템 넣지 않기" 반스코프 원칙(§11 counter-metric)과 정면으로 부딪히므로 gds-ux 세션에서 임의로 정하지 않는다 — PM/사용자 확인 필요.

## Inspiration & Anti-patterns

- **Lifted from 애니팡류 캐주얼 매칭**: 즉각적 피드백, 짧은 세션 단위, 낮은 학습 곡선.
- **Lifted from "돈버는 수족관" 사례** (PRD §4.3 근거): 광고를 별도 화면이 아니라 코어 루프의 감정 곡선(뽑기 직전 충동 정점, 스테이지 실패 직후)에 얹는 배치.
- `[UPDATED 2026-07-19]` **Rejected — 캔디크러시식 과포화 이펙트**: 30-50대+ 타겟에게 피로감을 유발하고 "가볍게 두뇌를 자극" JTBD와 어긋남 — 이 원칙은 유지. **단, 타이머 압박 자체는 더 이상 거부 대상이 아니다** — PRD §4.1이 이를 코어루프로 확정했다(`.decision-log.md` 2026-07-19). 대신 "과포화 이펙트"를 여전히 거부함으로써 압박은 있어도 산만하지 않은 절제된 표현을 유지한다.
- **Rejected — 두뇌 트레이닝 클리닉 톤**(중립 그레이, 클리니컬 아이콘): 법적 가드레일(치매예방 등 효능 주장 금지)과 정면 충돌하는 인상을 줄 위험.
- `[NEW 2026-07-19]` **Rejected — Brain Age류 "나이 환산" 프레이밍**: 결과 카드가 성과를 "반응속도 OO세"로 보여주는 방식은 Lumosity FTC 사례·Brain Age 비과학성 비판과 같은 패턴이라 판단, 동물 티어 프레이밍으로 대체(PRD §4.4, §10).

## Responsive & Platform

- 세로 모드 고정, 토스 인앱 웹뷰(주소창 없음) — 상단 세이프에어리어는 토스 자체 네비게이션 바를 고려해 확보.
- 작은 화면 기기에서도 매칭 그리드 열 수(3~4열, 기존 `columns` 로직)가 유지되도록 최소 타일 크기를 확보 — 타일이 48px 탭 타겟 미만으로 줄어들면 열 수를 낮춘다.
- 다크모드는 v1 스코프 밖 `[ASSUMPTION]` — PRD §11 counter-metric("완성도를 높이기 위해 출시를 늦추는 것")에 근거한 의도적 스코프컷. v2 후보.

## Key Flows

`[REWRITTEN 2026-07-19]` PRD 재작성으로 코어루프·뽑기 대상·온보딩 방식이 전면 바뀌면서 아래 4개 플로우를 UJ-1~4 기준으로 새로 썼다. 이전 버전(동물 캐릭터 수집 중심)은 `.decision-log.md` "Update session — 2026-07-19" 참고.

### Flow 1 — 미영(53세)이 첫 실행에서 암묵적으로 규칙을 익히고 첫 아이템을 얻는다 (UJ-1)

미영은 딸이 카톡으로 링크를 보내줘서 처음 앱을 켠다. 강제 튜토리얼 화면은 없다 — FR-9.

1. 콜드 오픈 → 별도 온보딩 화면 없이 바로 스테이지 1 진입. 스테이지 1~3은 고정 15초의 완화된 제한시간(그레이스 구간, `addendum.md` 초안)이라 사실상 여유롭게 규칙을 익히는 구간이 된다.
2. 타일을 탭해 짝을 맞춘다 — 맞을 때마다 `{colors.success}` 플래시로 즉각 확인. Timer bar는 평상시 톤(`accent`)이라 위협적으로 보이지 않는다.
3. 마지막 타일 쌍을 맞추자 클리어 다이얼로그: "스테이지 클리어! 재화 1개 획득."
4. 재화 배지가 카운트업하며 채워진다. 스테이지 2, 3도 같은 방식으로 이어서 클리어.
5. 재화가 뽑기 비용(3단위)에 도달하면 자연스럽게 뽑기 탭으로 유도(다이얼로그 내 "뽑으러 가기" 버튼).
6. 뽑기 캡슐을 탭 — 흔들림 → 오픈 → 첫 기능성 아이템 등장(시간 회복/오답 무효화/재화 2배 중 하나).
7. **Climax**: 아이템 리빌 직후, 처음으로 인벤토리 세그먼트에 들어가는 순간 1회성 컨텍스트 툴팁이 뜬다 — "이 아이템은 스테이지 시작 전이나 플레이 중에 써서 시간을 아낄 수 있어요." 여기서 처음으로 "이 재화와 아이템이 왜 존재하는지"가 이어진다.

실패 상황: 온보딩 구간(스테이지 1~3) 중 이탈 → 다음 콜드 오픈 시 그레이스 구간을 재시작하지 않고 멈춘 스테이지부터 이어서 진입(재방문 마찰 최소화) `[ASSUMPTION]`.

### Flow 2 — 재방문 유저가 개인 최고 기록 경신을 노리며 아이템을 소모한다 (UJ-2)

4일째 앱을 켠 미영이 출근 전 자투리 시간에 들른다. 지난 최고 기록은 스테이지 8.

1. 콜드 오픈 → 퍼즐 화면, 이전에 멈춘 스테이지부터 이어서. 헤더에 "최고 기록: 8" 표시.
2. 스테이지 6, 7을 가볍게 클리어 — 각 클리어마다 재화 획득 피드백과 Timer bar가 조금씩 더 빡빡해지는 게 느껴진다(FR-3, FR-4 난이도 곡선).
3. 스테이지 8 진입 — 이전 최고 기록과 같은 지점이라는 긴장감. 오답을 한 번 내며 Timer bar가 훅 줄어드는 걸 보고 남은 시간을 계산하며 서두른다.
4. 인벤토리 세그먼트로 세그먼트 전환 → 보유한 "시간 회복" 아이템을 스테이지 시작 전에 미리 소모(FR-13).
5. **Climax**: 스테이지 8을 클리어하는 순간 클리어 다이얼로그에 "최고 기록 경신!" 배지가 뜬다(FR-8) — "재화를 모은 이유"가 여기서 확인된다. 다음 스테이지로 계속 도전할지, 여기서 결과 카드를 확인할지 선택.

### Flow 3 — 타이머가 다 됐을 때 광고로 이어하거나, 재화가 부족할 때 광고로 무료 뽑기를 한다 (UJ-3)

같은 세션 안에서 두 개의 광고 트리거 지점을 미영이 각각 마주친다.

**3a. 스테이지 실패 → 광고로 즉시 이어하기 (FR-7, FR-17)**
1. Timer bar가 임계 구간(`error` 펄스)에 들어간 채 마지막 짝을 찾지 못하고 0에 도달 — 스테이지 실패.
2. 실패 다이얼로그: "시간이 다 됐어요! 광고 보고 이어할까요?" + 무료 재시도 버튼(Retry counter "1/2회") + 광고 시청 버튼.
3. 광고 시청 선택 → 보상형 광고 재생(플랫폼 SDK) → 시청 완료 → 제한시간 회복 후 같은 스테이지 즉시 이어하기.

**3b. 재화 부족 → 광고로 무료 뽑기 (FR-11)**
4. 뽑기 세그먼트에서 재화 부족 상태로 뽑기 버튼 탭 → "재화가 부족해요 — 광고 보고 무료로 뽑아볼까요?" 다이얼로그.
5. 광고 시청 선택 → 시청 완료 → 무료 뽑기 1회 즉시 지급, 캡슐 오픈 시퀀스로 자연스럽게 연결.
6. **Climax**: 두 경우 모두 광고를 봤다는 "손해" 느낌 없이 바로 다음 행동(이어하기/캡슐 오픈)으로 전환 — 대기 없는 즉시 연결이 핵심.

실패 상황: 광고 로드 실패 → "지금은 광고를 불러올 수 없어요" 토스트. 3a는 무료 재시도 경로(2회 한도 내)로, 3b는 재화 획득 경로(퍼즐 클리어)로 자연스럽게 유도. 무료 재시도 2회를 이미 소진한 상태에서 광고까지 실패하면 스테이지 처음부터 재시작만 가능(막다른 길 없음, 단 이어하기는 불가).

### Flow 4 — 딸이 결과 카드를 공유하고, 초대받은 부모님이 뽑기권을 만들어준다 (UJ-4)

서연(28세, 미영의 딸)이 먼저 이 앱을 플레이하다 결과 카드를 받는다.

1. 스테이지 클리어 다이얼로그에서 "결과 카드 보기" 링크 탭, 또는 세션을 끝내는 시점에 결과 카드 자동 노출.
2. **Climax(1)**: 결과 카드가 뽑기 캡슐과 같은 안무로 리빌된다 — 흔들림 → 오픈 → "반응속도 치타급!" 등급 카드 등장. 상위 티어라 `{colors.legendarySparkle}` 파티클까지 함께 터진다.
3. 서연이 공유 버튼 탭 → 네이티브 공유 시트(또는 `getTossShareLink`) → 카카오톡으로 미영에게 전송(FR-19, 항상 노출·보상 없음).
4. 미니앱 승인이 완료된 이후라면, 서연은 같은 화면에서 초대 버튼도 볼 수 있다 → 연락처에서 미영 선택 → `contactsViral`로 초대 발송(FR-20).
5. 미영이 링크를 통해 처음 미니앱을 실행한다 — 이것이 Flow 1의 시작점이 된다.
6. **Climax(2)**: 미영의 첫 실행이 확인되면 서연에게 아이템 뽑기권 1개가 지급된다(리워드 ID당 1일 1회 제한) — "귀여운 동물 자랑"에서 시작된 공유가 실질적 보상으로 돌아온다.

승인 전 상태: 초대 버튼(FR-20)은 숨겨지고 공유 버튼(FR-19)만 노출 — 서연은 공유는 항상 할 수 있지만 초대 보상은 미니앱 승인 이후에만 받을 수 있다(PRD §11 단계적 출시). 빈 상태: 아직 클리어 기록이 없어 결과 카드를 생성할 수 없는 유저는 공유 진입점 자체가 노출되지 않는다(첫 클리어 이후부터 등장) `[ASSUMPTION]`.
