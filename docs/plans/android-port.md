## 2️⃣ 브랜치 전략 — 분기하지 않는다 ✅ 확정

### 왜 플랫폼별 main을 만들지 않는가

**95%가 공용 코드인데 100%를 복제**하는 구조가 되기 때문이다. 앞으로 고칠 것(난이도 밸런스·가챠 확률·버그)은 전부 공용 영역이라 매번 양쪽에 cherry-pick해야 한다. 히스토리상 밸런스는 이미 여러 차례 재작성됐고(`b06a9ad`, `docs/respec-difficulty`), 그 패턴이면 divergence로 무너진다.

게다가 앱인토스는 현재 **잠정 중단** 상태다. 중단된 트랙을 위해 활성 트랙을 상시 이중 관리하는 것은 비용 방향이 거꾸로다.

### 채택: 단일 main + Vite alias 어댑터

`2026-08-18_play스토어-게임-poc-트랙-개설` 7️⃣의 *"삭제가 아니라 분기 처리로 두면 앱인토스 재개 시 그대로 살아난다"* 를 코드로 구현한다.

```
src/platform/
  types.ts          ← 공통 인터페이스 (Ads, Share, Leaderboard, Toast, Haptics)
  toss/index.ts     ← 기존 토스 구현 (보존)
  android/index.ts  ← AdMob + Web Share + 로컬 리더보드
```

호출부는 `import { ads } from "@platform"` 하나만 쓴다.

### 산출물 격리 — 실측 검증 완료 ✅

`[2026-08-21 실험]` "앱인토스 빌드가 무거워지지 않나"라는 우려를 **실제로 빌드해서 검증했다.** 양쪽 플랫폼에 고유 마커 문자열을 심고 각각 빌드한 결과:

| 빌드 | TOSS 마커 | ANDROID 마커 |
|---|---|---|
| `PLATFORM=toss` | **1개** | **0개** |
| `PLATFORM=android` | **0개** | **1개** |

빌드 로그도 `✓ 2 modules transformed` — 파일이 3개인데 2개만 읽었다. **번들러가 상대 플랫폼 파일을 열지도 않는다.**

원리: alias는 **정적 해석 단계**에서 갈린다. `@platform`이 빌드 타임에 `platform/toss`로 확정되면 `platform/android`는 import 그래프에 진입조차 못 한다. Tree-shaking(넣었다 빼기)이 아니라 **애초에 안 들어가는 것**이라 더 확실하다.

> ⚠️ **필수 제약 — 이걸 어기면 격리가 깨진다**
> `platform/index.ts`에서 **양쪽을 다 import한 뒤 런타임 `if`로 고르면 안 된다.** 그러면 둘 다 번들에 들어간다. 반드시 **alias로 갈라야** 한다.

### 참고: 현재 dist 33M은 우리 코드가 아니다

`[2026-08-21 조사]` 현 `dist/` 33M의 정체는 앱인토스 Granite가 뽑는 RN 번들이다 — 소스맵 6개 × 3.7M = **22M**, 실제 번들 1.6M × 6개(iOS/Android × RN 3버전). **어댑터로 추가되는 양은 여기 비하면 무시할 수준**이고, Play용 Capacitor 빌드는 순수 웹 번들이라 오히려 훨씬 가볍다.

## 4️⃣ 사운드 — 런칭 필수 아님 ✅ 확정

`[2026-08-21 확인]` 현재 오디오·햅틱 코드가 **전혀 없다**(grep 0건).

### 정책적으로 필수가 아니다

Play 심사에 사운드 요건은 없다. `2026-08-18_play스토어-게임-poc-트랙-개설` 8️⃣④의 "최소 기능 요건"은 *웹사이트를 그대로 감싼 껍데기 앱*을 걸러내는 조항이지 사운드와 무관하다. 오히려 기억력 퍼즐은 지하철·사무실에서 무음으로 플레이되는 비중이 높다.

### PoC 지표와 무관하다

`2026-08-20_poc-트리거-확정-앱인토스-유저획득채널-재포지셔닝`의 1차 기준은 **D+90 누적 설치 500**이다. 이건 **유입** 지표지 **리텐션** 지표가 아니다. 사운드는 리텐션 요소이므로 **지금 판정하려는 신호를 움직이지 않는다.** 철수 기준(100 미만)에 걸리면 통째로 매몰비용이 된다.

미루면 아끼는 비용: 에셋 라이선스 확인(상업적 이용), 음소거 토글 UI, 모바일 자동재생 정책 우회, APK 용량.

### 대신 햅틱을 넣는다

이 게임은 **"틀리면 즉시 끝"** 인데 실패 피드백이 전부 시각 채널에 몰려 있다(`wrongIds`, `showPenalty`, `showFailureBanner`). 실기기 피드백에서 이미 *"순차 숨김이 너무 가혹하다"* 는 지적이 나왔던([PuzzlePage.tsx:677](src/pages/PuzzlePage.tsx:677)) 것과 같은 계열의 **피드백 명료도** 문제다.

`navigator.vibrate()`는 **에셋 0바이트·30분 내외**이고, 무음 모드에서도 동작해 사운드보다 도달률이 높다. 매치 성공 시 짧게, 미스매치 시 조금 길게.

동물 소재라 13세 미만으로 분류되면 **개인화 광고가 금지**되어 eCPM이 급락한다. **"AdMob을 붙이면 수익 라인이 열린다"는 전제가 반쯤 깎일 수 있다.**

#### `[2026-08-21]` 콘솔 확인 결과

Play Console 「앱 콘텐츠」 항목을 진행했다. 선행 의존이 있어 **광고 → 앱 액세스 권한 → 타겟층** 순으로 열린다.

| 항목 | 답변 | 결과 |
|---|---|---|
| 콘텐츠 등급 (IARC) | — | ✅ **전체이용가 3세** = 목표 달성 |
| 광고 | **있음** | ✅ 출시 시점 기준으로 답해야 함 (허위 신고는 앱 정지 사유) |
| 앱 액세스 권한 | **제한 없음** | ✅ 로그인·서버 없음(`localStorage`만) |
| 타겟층 | **13세 이상만** | ✅ **기본 설문 저장 완료, 경고 없음** |

> ⚠️ **IARC "3세"와 타겟층은 별개 축이다.** IARC는 *콘텐츠가 유해한가*, 타겟층은 *누구를 겨냥하는가*를 잰다. 전체이용가여도 타겟은 13세 이상으로 신고할 수 있고, **그래야 한다**. 오히려 청소년이용불가가 되면 자체등급분류에서 빠져 0원 트랙이 깨진다.

#### 리스크의 성격이 바뀌었다

- ❌ ~~"설문 단계에서 막힌다"~~ → **아님. 경고 없이 통과**
- ✅ **"등록정보·APK 제출 후 재판정에서 뒤집힐 수 있다"** ← 실제 리스크

앱 세부정보·앱 정보 섹션이 뜨지 않은 이유는 **판정 재료가 없기 때문**이다. 구글은 아이콘·스크린샷·설명·APK를 보고 "어린이 관심 유도"를 판정하는데 전부 미제출 상태다.

구글이 명시한 판정 기준이 이 게임과 정면으로 겹친다:

| 구글 기준 | 이 게임 |
|---|---|
| 아동이 좋아할 만한 **동물 캐릭터** | 🐶🐱🐰🐻🐼 — 핵심 소재 |
| 유아용 **색상** | `#BA68C8` 밝은 보라 |

> **신고한 타겟층과 무관하게, 어린이를 타겟팅하는 것처럼 보이는 이미지·용어가 평가에 영향을 준다** — Play Console 고객센터

#### 결론: 이 리스크는 포팅을 막지 않는다

최종 확인에 **APK가 필요**하므로 순서가 뒤집힌다:

```
포팅(1~4단계) → APK + 등록정보 → 비공개 트랙 업로드 → 최종 판정
```

→ **goal 착수의 선행 조건이 아니다.** 7️⃣의 순서에서 Families 확인이 IARC보다 앞선다는 원칙은 유지되지만, *완전한* 확인은 3단계 PR 이후에만 가능하다.

#### 대응

- **회피 시도:** 스토어 등록정보를 "귀여운 동물 게임"이 아니라 **"반응속도·기억력 훈련"** 으로 프레이밍. 티어(`치타급`)·기록 경쟁을 전면에. 실제 그런 게임이므로 **정직한 프레이밍**이지 위장이 아니다
- **재분류 시:** AdMob은 계속 쓸 수 있고 **단가만 떨어진다**(`setTagForChildDirectedTreatment(true)` + `setMaxAdContentRating("G")` 필요). 기준을 낮추지 않고 **1차 유저 신호를 주 판정선으로 승격**, 금액을 참고치로 내린다

#### 아직 남은 콘솔 항목 (출시 전 필수)

- **개인정보처리방침** — AdMob이 광고 ID를 수집하므로 **URL 필요**. 문서 작성 + 호스팅(GitHub Pages 등) 리드타임 있음
- **데이터 보안** — 게임 자체는 아무것도 전송하지 않으나 **AdMob의 광고 ID 수집**을 신고해야 함

### ② Java 22 ↔ Gradle 호환

3단계에서 터질 가능성이 가장 높은 지점. `JAVA_HOME`을 Corretto 21로 고정한다(5️⃣ 참조).

### ③ 런타임 분기 유혹

편의상 `platform/index.ts`에서 양쪽을 import하면 **격리가 조용히 깨진다.** 조건 3·4가 이걸 잡도록 설계돼 있으므로 **매 PR마다 검사**한다.

### ④ TDS 컴포넌트 대체

`Button` `useToast` `useDialog` 3종이 Play 빌드에서 필요하다. 경량 자체 구현으로 대체하되 **시각적 동등성**은 목표가 아니다 — 게임 화면은 자체 스타일이고 TDS는 주변부에만 쓰인다.
