# 앱인토스 카피라이팅

앱인토스 미니앱의 마케팅 카피를 쓴다. 이 스킬이 존재하는 이유는 두 가지다.

**첫째, 심사 규칙이 공식 문서에 없다.** 의문문 금지, 명령형 `~세요` 금지, 제목 명사형
종결 — 전부 반려를 맞아가며 역산한 것이다. 규칙을 모르고 쓰면 반려되고, 반려 1회는
영업일 2~3일이다. 발송 기간이 정해진 캠페인에서 이 손실은 카피 품질보다 치명적이다.

**둘째, 같은 실패를 이미 반복했다.** 2026-09-15에 명령형 규칙을 놓쳐 반려됐는데,
그 규칙은 3일 전 노트에 이미 적혀 있었다. 노트의 가치는 작성이 아니라 재사용에 있고,
이 스킬이 그 재사용을 강제하는 장치다.

## 작업 순서

카피를 쓰기 전에 이 순서를 지킨다. 특히 1·2번을 건너뛰면 규칙 위반이나 허위 소구가
섞여 들어간다.

1. **채널을 확정한다** → `references/channels.md`에서 해당 채널의 제약을 읽는다
   (글자 수·심사 여부·톤 허용 범위가 채널마다 다르다)
2. **심사 채널이면 규칙표를 읽는다** → `references/review-rules.md`
3. **소구 축을 정한다** → 아래 "소구 축 선정"
4. **카피를 쓴다** → 아래 "카피 원칙 4개"
5. **숫자·사실을 코드에서 검증한다** → 아래 "사실 검증"
6. **심사 채널이면 체크리스트로 자가 검수한다** → `references/review-rules.md` 하단

## 카피 원칙 4개

토스가 제공한 마케팅 Tips와 실측을 종합한 것이다.

### 1. one message — 핵심 메시지 하나만

호기심 유발이 가장 강력하다. 제목과 본문이 **같은 장면**을 가리켜야 한다.
제목은 기억력 게임인데 본문은 가챠면 메시지가 둘이라 아무것도 전달되지 않는다.

### 2. 구체성 — 숫자 삽입이 아니라 장면이 그려지는 것

이걸 오해하면 이렇게 된다:

```
❌ 평균 3스테이지        사람이 쓰는 말이 아니다. 대시보드 지표 같다
❌ 15초 기억력           명사 두 개를 붙였을 뿐 문장이 아니다
✅ 동물이 숨기 전에 짝을 찾아 봐요    장면이 보인다
```

"성격테스트 도착! 5개 질문에 답하기"가 CTR을 몇 배로 올린 건 5라는 숫자 때문이 아니라
**읽는 순간 뭘 하게 될지가 보여서**다. 숫자는 장면을 선명하게 만드는 도구이지 목적이 아니다.

### 3. 짧게 — 길면 잘려서 인지 자체가 안 된다

안드로이드 비중 67%, 큰글자모드 사용 25%. 문구가 길면 글자가 잘린다.
글자 수 상한을 꽉 채우지 않는다 — 반려 후 수정할 여유가 사라진다.

### 4. 직관성 — 읽는 즉시 이해돼야 한다

소리 내어 읽어보고 어색하면 버린다. 어색한 카피는 구체성이 아무리 높아도 못 쓴다.

### ⚠️ 궁금증은 빈칸에서 나온다

```
❌ 스테이지 3에서 대부분 멈춰요       답을 다 말했다. 정보를 주고 끝난다
✅ 스테이지 10부터 동물이 변장해요   "변장? 어떻게?" — 답은 클릭해야 안다
```

정보를 완결하면 클릭할 이유가 사라진다. 후킹은 남긴 빈칸의 크기에 비례한다.

## 소구 축 선정

### 소재 2개는 A/B 실험이 아니다

스마트발송에 소재를 2개 넣으면 토스 AI가 pCTR로 실시간 자동 배분한다.
**내가 사후에 우열을 판정하는 A/B 실험과는 다른 개념이다.**

| | 표본 부족할 때 |
|---|---|
| A/B 실험 (내가 판정) | ❌ 불가능 |
| 소재 2개 (AI 자동 배분) | ✅ 무관하게 작동 |

그래서 소재는 항상 2개 넣는다. 1개만 넣으면 그 기능을 스스로 끄는 것이다.

### 🚫 축이 갈리지 않은 2안은 2안이 아니다

실제로 저질렀던 실패:

```
a안  동물 짝을 맞춰 다음 스테이지로 가 봐요.
b안  동물 짝 맞추기로 내 최고 기록을 세워 봐요.
```

사실상 같은 말의 변주다. 2개를 넣고도 AI에게 준 선택지는 하나였다.
**두 소재는 서로 다른 욕구 축이어야 한다.**

### 욕구 축 고르기

제품 구조와 맞지 않는 축은 CTR이 올라도 리텐션을 무너뜨린다.
"편하게 즐기세요"로 데려온 유저는 난이도를 만나는 순간 이탈한다.
**카피는 실제 경험과 일치해야 한다.**

| 축 | 언제 쓰나 | 주의 |
|---|---|---|
| 호기심 | 거의 항상 유효. 가장 강력 | 답을 다 말하면 죽는다 |
| 자기 검증 | 등급·점수·기록 체계가 있을 때 | "나를 측정"으로 번역 |
| 승부욕·경쟁 | 리더보드·티어·리셋 구조가 있을 때 | 광고 심사에서 도발 톤은 제약. 결과 카드·공유가 본진 |
| 이득·보상 | 실제 보상이 있을 때만 | 없으면 허위 소구 |
| 휴식·힐링 | 실제로 쉬운 제품일 때만 | 어려운 제품에 쓰면 최악. CTR↑ 리텐션↓ |

**승부욕이 본진이어도 광고성 푸시에서는 온전히 표현되지 않는다** — 미경험자에게
"나무늘보급 탈출"은 맥락이 없다. 이럴 때 호기심·자기 검증은 승부욕을 미경험자가
이해할 수 있게 **번역한 것**으로 쓴다:

| 축 | 승부욕의 번역 |
|---|---|
| 자기 검증 | "남과 비교" → "나를 측정" |
| 호기심 | "이겨라" → "결과가 궁금하다" |

## 사실 검증

카피에 숫자나 단정적 표현을 넣기 전에 **코드에서 근거를 찾는다.** 근거가 없으면 쓰지 않는다.

측정 자체가 불가능한 것을 쓰면 안 된다. 예를 들어 "상위 1%"는 순위 조회 API가 없어
산출이 불가능했고(`leaderboard.ts` 주석), 모수도 8명이었다. 심사 반려 위험에 더해
표시광고법상 실증 책임 대상이고, 무엇보다 **클릭한 사람이 존재하지 않는 것을 근거로
클릭하게 된다.** "아무도 안 물어볼 것"은 우리가 통제할 수 없는 조건이다.

근거를 찾을 만한 곳:

| 찾는 것 | 어디 |
|---|---|
| 난이도·제한시간·구간 전환 | `src/game/balance.ts` |
| 등급·티어 경계 | `src/game/leaderboard.ts` |
| 아이템·비용·확률 | `src/game/items.ts` |
| 기존 문구 톤 | `src/i18n/locales/ko.ts` |

**사실 제약은 창의성의 적이 아니다.** "상위 1%"를 포기하고 찾은
"스테이지 10부터 동물이 변장해요"가 후킹이 더 강했다 — 등급은 클릭 후에나
확인되지만 변장은 즉시 장면이 그려지고 "어떻게?"가 따라온다.

## 반려 대응

반려되면 사유를 **규칙으로 역산**한다. 개별 문구를 고치는 게 아니라 "무엇이 금지인가"를
추출해 `references/review-rules.md`에 추가한다. 심사 AI의 판정 기준은 공식 문서에
없으므로 이 파일이 유일한 기록이다.

**같은 소재가 2회 반려되면 그 안은 버리고 통과한 소재로만 간다.** 발송 기간은
반려-수정 사이클마다 줄어든다. A/B 비교 데이터보다 실제 발송이 나가는 것이 우선이다.

대조군을 활용한다 — 같은 회차에 통과한 소재가 있으면 둘의 차이가 곧 규칙이다.
`내 등급 확인`(반려) vs `기억력 테스트`(통과)에서 "서술성 명사 종결이 문제"가 나왔다.

## 성과 판단

| 지표 | 기준 |
|---|---|
| CTR | 발송 1,000명당 5% 넘으면 성과 좋음 |
| 판정 가능 최소선 | 클릭 25건 또는 발송 2,500건 |

### ⚠️ 발송량이 안 늘면 카피 문제다

스마트발송은 머신러닝으로 반응할 유저를 찾아가며 발송량을 늘린다.
**5일이 지나도 발송량이 적다면 CTR이 낮아 발송이 밀리는 것이다.**

```
CTR 낮음 → pCTR 랭킹에서 밀림 → 발송량 안 늘어남 → 표본 부족 → CTR 못 올라감
   ↑                                                                │
   └────────────────────────────────────────────────────────────────┘
```

표본이 부족하다는 사실에서 "기다리면 된다"를 도출하면 안 된다.
**발송량은 외생변수가 아니라 CTR의 함수다.** 탈출구는 카피 교체뿐이다.

지표가 안 움직일 때는 그 지표가 다른 지표의 함수인지 먼저 묻는다.

## 🚨 기획 단계에서 먼저 할 것

**카피라이팅은 출시 후 마케팅 작업이 아니라 기획 단계의 제품 설계 입력값이다.**

실제로 겪은 순서는 이랬다:

```
기획 → 개발 → 출시 → "이제 어떻게 알리지?" → 채널 발견 → 카피 반려 5회
→ 3차 수정 → 채널 자체가 종료
```

채널을 나중에 발견했고, 제약을 카피를 써보면서 하나씩 알아냈다. 그 결과 쓸 수 있는
후킹을 **이미 만들어진 것에서 사후에 찾아내야** 했다. 운 좋게 재료(변장·티어)가
있었지 없었다면 쓸 카피가 없었다.

거꾸로 갔어야 한다 — **"이 제품을 7자로 어떻게 알릴 것인가"를 먼저 정하고, 그 문구가
사실이 되도록 제품을 설계한다.** 그러면 후킹은 찾는 게 아니라 설계된다.

기획 단계에서 선행할 것:

1. 쓸 수 있는 마케팅 채널을 전부 나열한다
2. 각 채널의 제약을 확보한다 (글자 수·심사 규칙·자격 요건·종료 일정)
3. 그 제약 안에서 카피 초안을 쓴다 — **개발 착수 전에**
4. 그 카피가 사실이 되도록 제품을 설계한다

토스 홈 광고·피처드 선정 기준도 같은 이야기다. 체류시간·재방문률·방문수로 평가되는데,
이걸 미리 알면 그 방향으로 제품을 설계할 수 있다. 다 만든 뒤에 알면 남는 선택지는
카피 수정뿐이다. **채널의 평가 기준을 모르고 만들면, 만든 뒤에 할 수 있는 일이 거의 없다.**
